API reference

API reference

The API of Runink PULSE: Prescriptive Unified Lead & Social Engine is gRPC, package pulse.v1. The contracts are PULSE's .proto files. Browsers use gRPC-Web on the same port. The few plain HTTP routes are listed under HTTP endpoints. To call the API, see Calling the API.

The service pages below are generated from the protos and from the server's role table, and a check fails when they fall behind, so every method listed is one the server has.

  • HTTP endpoints
  • Brand analysis and audits: Audit pipeline, diagnosis, research, Search Console, website repository
  • Leads, tenders and accounts: Leads and public tenders, AI calls, Integrations, agencies
  • Campaigns and results: Campaigns, plans, Autopilot, automations, metrics
  • Studio and content: Content, Studio, skills, publishing
  • AI and platform: Model, activity, identity, config, self-heal
  • Shared components: Billing, Connections, Profile, Access, Voice, Comms
  • Common types: commons.proto and unused types

Conventions

  • Authentication. Every method needs authorization: Bearer <accessToken>, except the ones whose least role is "none (public)" and gRPC reflection. The browser client authenticates with a session cookie instead; see Calling the API.
  • Roles. Each method has a least role, read fresh from your account on every call: viewer for reads that spend no model time and change nothing, editor for anything that generates, writes, dials out or places a call, and admin for access and messaging settings. A call below your role fails with PermissionDenied. "Any signed-in" methods (who am I, sign out) work for an account with no role. Some methods check more than the role (an admin row, an arming switch); the page notes say which.
  • Scoping. Data is scoped to the signed-in user. Request fields named user_id do not let you read another user's data.
  • Streaming. AI generators return stream StreamChunk. See Common types.
  • Errors. Standard gRPC status codes with a human-readable message. See Troubleshooting.

Shared services

These come from Runink's shared component library and are documented on Shared components: runink.ui.billing.v1.BillingService, runink.ui.datasources.v1.ConnectionsService and RunnersService, runink.ui.profile.v1.ProfileService, runink.ui.access.v1.AccessService and runink.ui.comms.v1.CommsService.
