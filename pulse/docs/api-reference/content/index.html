      Studio and content

      Studio and content

      The services behind Studio (formats, skills, the library) and the content records that Campaigns show and publish. Package pulse.v1; the least role of each method is in its table. See Studio.

      Notes

      • Our own model only. Everything here generates on the platform’s own inference plane through the model router. There is no image-generation tier: GenerateCreative for a still image answers Unimplemented.
      • Skills run as one bounded pipeline: OpenBias on the inputs, the prompt, TOON output, Go checks, one revision only when a check failed, OpenBias on the draft, then the plan gate. Drafts land on the board with their scores in content.metadata.
      • Publishing queue. status is pending, publishing, posted, withheld or failed. reason_status is recorded, none, missing or unavailable: never read an empty reason as “nothing to report” without checking it.
      • Speech comes from TIDE’s shared ttsd (TTSD_URL). When it is switched off, a method that needs speech answers Unavailable rather than silence.

      pulse.v1.ContentService, declared in pulse.proto.

      MethodRequest → ResponseLeast roleNotes
      GenerateContentGenerateContentRequest → stream StreamChunkeditorGenerateContent streams AI-generated content for a specific channel and topic.
      ListContentListContentRequest → ListContentResponseviewerListContent returns paginated content pieces.
      UpdateContentUpdateContentRequest → ContenteditorUpdateContent edits a suggested draft’s title/body/hashtags/CTA before it is approved or rejected.
      SaveGeneratedContentSaveGeneratedContentRequest → ContenteditorSaveGeneratedContent persists a piece of studio-generated content so it gets a content_id that Approve/Schedule can act on, and returns the stored Content.
      ApproveContentApproveContentRequest → ContenteditorApproveContent marks content as approved for publication.
      RejectContentRejectContentRequest → ContenteditorRejectContent marks content as rejected with reviewer notes.
      CreateCreativeCreateCreativeRequest → CreativeeditorCreateCreative creates a new creative asset (image prompt, video script, etc.)
      ListCreativesListCreativesRequest → ListCreativesResponseviewerListCreatives lists creative assets for a campaign or content piece.
      UpdateCreativeUpdateCreativeRequest → CreativeeditorUpdateCreative updates a creative asset’s metadata or content.
      DeleteCreativeDeleteCreativeRequest → google.protobuf.EmptyeditorDeleteCreative soft-deletes a creative asset.
      GenerateCreativeGenerateCreativeRequest → stream StreamChunkeditorGenerateCreative generates a real AI image (via local stable-diffusion.cpp or a configured remote image-gen service) from a prompt and persists it as a Creative — unlike CreateCreative, which only registers metadata for an already-uploaded asset.
      AttachContentMediaAttachContentMediaRequest → AttachContentMediaResponseeditorAttachContentMedia attaches the caller’s own uploaded photo or video (an AuditAttachmentService upload) to a piece as a creative, sealed in the media vault, so Instagram can publish it as a post, Reel or Story. On an Instagram piece the file is checked against Instagram’s documented rules first (FAILED_PRECONDITION with the reason in plain words).

Missing assets are made on demand (an Instagram post’s image). Nothing is published.

      SkillService

      SkillService — PULSE’s content skills (grpc/agents/skills/CHANNEL/SKILL/SKILL.md). A skill is one bounded run on PULSE’s own inference: the model writes a TOON draft, deterministic Go checks score it, OpenBias screens the request and the draft, and the plan gate judges it. A draft the guard or the gate withholds is never returned or saved. Nothing a skill writes is published or sent by itself: drafts land on the board for a person to approve, and publishing stays behind PULSE_APPLY_ENABLED plus the channel’s own switch.

      pulse.v1.SkillService, declared in skills.proto.

      MethodRequest → ResponseLeast roleNotes
      ListSkillsListSkillsRequest → ListSkillsResponseviewerListSkills lists the skills, optionally for one channel and/or format (the Studio card’s format). No model, no write.
      RunSkillRunSkillRequest → RunSkillResponseeditorRunSkill runs one skill (by id, or the first for channel+format) and, when save_draft is set, saves a kept draft to the board with its scores.

message RunSkillResponse {

  string title = 2;
  string draft_text = 3;

  repeated SlideImage slide_images = 15;

  // palette when PULSE has no brand colours).
  repeated string slide_images_notes = 16;

  // the skill does not size hashtags.
  repeated HashtagSize hashtag_sizes = 17;

// One rendered carousel slide.
message SlideImage {
  int32 n = 1;        // slide number, from 1
  string url = 2;     // a signed /media/ URL (expires; never stored)
  string alt_text = 3;
  int32 width = 4;
  int32 height = 5;
}

// One hashtag's size: posts a day, measured from Instagram's hashtag search
// and recent media for the account's own connected professional account.
message HashtagSize {
  string tag = 1; // "#sourdough"
  // measured | not_measured | unreadable. not_measured: no connected account,
  // or the 30-hashtags-a-week budget is spent; unreadable: Instagram refused
  // (reason says what to reconnect with).
  string state = 2;
  // Set only when measured; absent is not 0.
  optional double posts_per_day = 3;
  string band = 4;   // niche | medium | broad (measured only)
  string reason = 5; // how it was measured, or why not
  int32 sample = 6;  // posts the figure counted
}

      SERVICE 16: PublishingService (Cacarejar-style Automation)

      pulse.v1.PublishingService, declared in pulse.proto.

      MethodRequest → ResponseLeast roleNotes
      SchedulePostSchedulePostRequest → ScheduledPosteditor
      ListScheduledPostsgoogle.protobuf.Empty → ListScheduledPostsResponseviewer
      ListChannelReadinessgoogle.protobuf.Empty → ListChannelReadinessResponseviewerListChannelReadiness says, for every channel, whether a post scheduled there now would go out, and if not why: from the same functions the dispatcher gates on, so the answer cannot disagree with what dispatch does.

      // ChannelReadiness is one channel's publishing answer for the caller.
message ChannelReadiness {
  Channel channel = 1;
  // publisher is the outward publisher's arming key ("linkedin", "youtube",
  // "blog", …), or empty when PULSE has no publisher for this channel: its
  // content is drafted and scheduled, never sent.
  string publisher = 2;
  // publisher_note explains a publisher that exists and cannot post today,
  // or the absence of one. Empty when the publisher can post.
  string publisher_note = 3;
  // armed is the kill switch AND the channel's own switch; armed_reason names
  // the layer that decided, in the dispatcher's own words.
  bool armed = 4;
  string armed_reason = 5;
  // owner_gated: the channel publishes with the deployment's credential, so
  // only allowlisted owners may publish through it. owner_allowed is whether

// ScheduledPost is one row of the Publishing queue.
//
// reason/reason_status carry the OUTCOME'S EXPLANATION, following the same
// value+provenance pairing AuditCheck uses for status/notes. A row can stop
// short of publishing for reasons that demand different responses — the kill
// switch was off (withheld), the OAuth token is dead, the platform returned a
// quota error (both failed) — and `status` alone renders all three as one
// indistinguishable "it did not publish".
//
// reason_status exists so an ABSENT reason is never rendered as an empty
// string, which reads like "nothing to report":
//
//   "recorded"    — reason holds the recorded explanation.
//   "none"        — the outcome needs no explanation (pending/publishing/
//                   posted). An empty reason is correct here.
//   "missing"     — the outcome DEMANDS an explanation (withheld/failed) and
//                   none was recorded. Say the reason is missing; never blank.
//   "unavailable" — the reason could not be read at all (e.g. a pre-migration
//                   database restored from a replica). The row is still real;
//                   its explanation is simply not retrievable.
message ScheduledPost {
  string id = 1;
  string content_id = 2;
  Channel channel = 3;
  google.protobuf.Timestamp scheduled_at = 4;
  string status = 5;
  // reason is ONLY ever the recorded explanation, never prose about its own
  // absence — that is reason_status's job, so the two never have to be
  // disambiguated by inspecting the string.
  string reason = 6;
  // reason_status is "recorded" | "none" | "missing" | "unavailable".
  string reason_status = 7;
  // Where it went out ("" = not posted, or the platform gave no link).
  string published_url = 8;
  // Where the post came from: "campaign" (source_name is its name),
  // "checkup" (source_at is when that check-up ran), "autopilot", or ""
  // (scheduled by hand, or not known).
  string source = 9;
  string source_name = 10;
  google.protobuf.Timestamp source_at = 11;
  // not_connected: the send failed because the channel's account is not
  // connected, so PULSE will not post it (the person can download it).
  bool not_connected = 12;
  // When the post was queued (its row was written).
  google.protobuf.Timestamp created_at = 13;
  // When it went out, was withheld, failed or was missed; unset while it
  // waits, and for rows that ended before this was recorded.
  google.protobuf.Timestamp finished_at = 14;
}

message SchedulePostRequest {
  string content_id = 1;
  Channel channel = 2;
  google.protobuf.Timestamp scheduled_at = 3;
}

message ListScheduledPostsResponse {
  repeated ScheduledPost posts = 1;

      BrandPaletteService

      BrandPaletteService — the colours and logo PULSE draws an account’s carousels, post images and videos with (release 8). Read from the audited site (its CSS, theme colour and logo) when the audit runs; the owner may override any of them. Text colours are checked for WCAG AA contrast; a colour that fails is replaced by the nearest shade that passes and the note says so. With none known the palette is PULSE’s neutral one.
