Studio and content

Studio and content

The services behind Studio (formats, skills, the library) and the content records that Campaigns show and publish. Package pulse.v1; the least role of each method is in its table. See Studio.

Notes

  • Our own models only. Everything here generates on the platform's own models. Still images are ImageService's: only a person asks for one, each is an "AI-generated" draft until a person approves it, and GenerateCreative for a still image answers FailedPrecondition and points there.
  • Skills. Each content type is a skill with its own checks; drafts pass PULSE's safety rules and the plan gate, and land on the board with their scores in content.metadata.
  • Publishing queue. status is pending, publishing, posted, withheld or failed. reason_status is recorded, none, missing or unavailable: never read an empty reason as "nothing to report" without checking it.
  • Speech comes from the platform's speech service. When it is off, a method that needs speech answers Unavailable rather than silence.

// PublishOutcomeKind is how an approval or a send ended. Publishing is never
// a dead end (owner, 2026-11-20): it ends published, on its way, or with the
// content ready to download.
enum PublishOutcomeKind {
  PUBLISH_OUTCOME_KIND_UNSPECIFIED = 0; // not approved, or nothing recorded
  PUBLISH_OUTCOME_PUBLISHED = 1;        // sent to the channel
  PUBLISH_OUTCOME_SCHEDULED = 2;        // queued: the publishing worker sends it at its time

  // lost and the piece can be downloaded with DownloadContent.
  PUBLISH_OUTCOME_DOWNLOAD_READY = 4;
}

SkillService

SkillService — PULSE's content skills. A skill is one bounded run that writes a draft for a channel and format; the draft is checked and reviewed, and a draft that fails the review is never returned or saved. Nothing a skill writes is published or sent by itself: drafts land on the board for a person to approve, and publishing stays behind the deployment's and the channel's own publishing switches.

// ScheduledPost is one row of the Publishing queue.
//
// reason/reason_status carry the OUTCOME'S EXPLANATION, following the same
// value+provenance pairing AuditCheck uses for status/notes. A row can stop
// short of publishing for reasons that demand different responses — publishing
// was switched off (withheld), the OAuth token is dead, the platform returned a
// quota error (both failed) — and `status` alone renders all three as one
// indistinguishable "it did not publish".
//
// reason_status exists so an ABSENT reason is never rendered as an empty
// string, which reads like "nothing to report":
//
//   "recorded"    — reason holds the recorded explanation.
//   "none"        — the outcome needs no explanation (pending/publishing/
//                   posted). An empty reason is correct here.
//   "missing"     — the outcome DEMANDS an explanation (withheld/failed) and
//                   none was recorded. Say the reason is missing; never blank.

//                   database restored from a backup). The row is still real;
//                   its explanation is simply not retrievable.

  // disambiguated by inspecting the string.

  string reason_status = 7;

  string published_url = 8;

LipSyncVideoService makes a lip-synced presenter video of the caller's own twin from a script, using the person's own photo or short video.
