      Brand analysis and audits

      The services behind Brand Analysis: the one-line audit and its stages, the diagnosis, material attached to a new-site audit, content research, market research, Google Search Console, and fixes proposed to the customer’s own website repository. Package pulse.v1; the least role of each method is in its table. See Audit a domain.

      Notes

      • One deadline. GenerateDiagnostic and a score-only RunAudit run under one end-to-end budget, PULSE_AUDIT_DEADLINE_SECONDS (170 seconds by default). Each phase gets a budget from what is left; a phase that does not finish is named on the result as not completed within the budget, and the diagnosis is returned as a partial result rather than discarded.
      • Judged output. Diagnostic.channel_prescriptions and brand_visibility hold only proposals the judging ladder kept; judgements lists every verdict.
      • Audit runs. RunAudit runs the stages detached from the call (bounded at 45 minutes), resumes from the first stage not done, reuses a run from the last 24 hours unless force is set, and attaches to a run already in flight. score_only runs just normalize and score on the URL as given; an identical score-only run within PULSE_AUDIT_CACHE_TTL (one hour by default) is reused unless force. Read the report with GetAuditRun (AuditRun.score_report).
      • Stages. stage is a stable identifier: show it as-is or map it to your own labels, but do not rely on the set of stages or their order. A stage that could not run because an earlier one did not finish is skipped, with an error that starts blocked:. queue_position is set while a stage waits for model capacity. The terminal event has an empty stage and the run’s final run_status. With TIDE_HEALTH_URL set, each stage reports to agent health as pulse-audit-<stage>.
      • Stored reads. The Radar List* methods read what earlier research and audits persisted; they search nothing and spend no model time. Guest opportunities found by Radar are saved onto Influencers, scored by topical relevance, never by an audience figure.
      • Changing a site. ApplyAuditActions modes other than plan need PULSE_APPLY_ENABLED=true, PULSE_AUDIT_APPLY=true and an admin; every mode needs repo_path inside PULSE_APPLY_ROOT. SiteRepoService.ProposeSiteFix needs the same two switches and an admin, writes only to a new pulse/<run>-<finding> branch and opens a pull request. ConnectSiteRepo and DisconnectSiteRepo also check for an admin, although their table role is editor. See Website repository.
      • Search Console. StartSearchConsoleConnect returns Google’s consent address; Google returns to /oauth/search-console/callback. Without the Google OAuth client or an https PULSE_PUBLIC_BASE_URL the answer says what is not set up. See Google.

      AuditPipelineService

      The one-phrase audit pipeline (“Audit example.com”): the user types a domain and every PULSE page is populated by inference — crawl, site score, trend slice, the diagnosis, the deterministic fan-out (campaign, approval drafts, follow-up cycle, schedule, creatives, course, persona, radar summary), then radar research and leads. Every stage is tracked (audit_runs / audit_stages), owner scoped, and reported honestly: a stage is done only when it wrote at least one row or recorded “0 found” from a source that actually answered. A run whose required stage failed ends partial or failed, never completed.

      pulse.v1.AuditPipelineService, declared in pulse.proto.

      MethodRequest → ResponseLeast roleNotes
      RunAuditRunAuditRequest → stream AuditProgresseditorRunAudit starts (or attaches to, or resumes) the caller’s audit of a domain and streams stage progress until the run ends. A second call for the same (caller, domain) while a run is active attaches to it; a call after a failed/partial run resumes from the first stage that is not done; a call within 24h of a completed run returns that run unless force is set. A score_only call is its own run: it never attaches to or replays a full audit (nor a full audit to it); see RunAuditRequest.score_only.
      GetAuditRunGetAuditRunRequest → AuditRunviewer
      ListAuditRunsListAuditRunsRequest → ListAuditRunsResponseviewer
      GetAuditAiVisibilityGetAuditAiVisibilityRequest → AuditAiVisibilityviewerGetAuditAiVisibility returns what a run’s genai_visibility stage measured, finding by finding, with the evidence for each.
      GetAuditFindingsGetAuditFindingsRequest → AuditFindingsviewerGetAuditFindings returns what a run found for the business: leads with their contacts, possible competitors, where it wins and loses against each, niches worth exploring and partners with their contacts. Each kind says whether it was found, found nothing, or was not measured.
      DeleteAuditRunsDeleteAuditRunsRequest → DeleteAuditRunsResponseeditorDeleteAuditRuns deletes some of the caller’s full audit runs, or every run of one domain but the newest (all_but_latest, with the domain typed back as confirm). Removed: each run, its stages, its findings, its AI-visibility rows and its content-gaps snapshot unless a campaign plan uses it. Kept: leads, campaigns, drafts, the diagnosis and the site-score history. A run still in flight is refused, never deleted.
      GetAuditAudienceGetAuditAudienceRequest → AuditAudienceviewerGetAuditAudience returns who a run found the business sells to and what it sells (the research inputs it saved), each with where it came from.

      Also uses AuditAction.

      // AuditReport is the full audit result: the output contract of the scoring
// engine. overall_score is the weighted mean of composites; benchmark_mode is
// "relative" or "absolute"; skipped_data_sources lists adapters the user could
// configure to raise coverage.
message AuditReport {
  string url = 1;
  google.protobuf.Timestamp audited_at = 2;
  double overall_score = 3;
  repeated AuditComposite composites = 4;
  repeated string skipped_data_sources = 5;
  string benchmark_mode = 6;
  repeated AuditRecommendation recommendations = 7;
  repeated AuditAction actions = 8;
}

// AuditComposite is one of the four scored dimensions. coverage is the fraction
// (0-1) of the composite's weight that was actually scored — a 90 at 0.4
// coverage is very different from a 90 at 1.0.
message AuditComposite {
  string id = 1;
  string label = 2;
  double score = 3;
  double weight = 4;    // normalized 0-1
  double coverage = 5;  // 0-1
  repeated AuditSignal signals = 6;
}

// AuditSignal is a scored signal within a composite.
message AuditSignal {
  string id = 1;
  double score = 2;
  double weight = 3;    // normalized 0-1 within its composite
  double coverage = 4;  // 0-1
  repeated AuditCheck checks = 5;
}

// AuditCheck is a single check's outcome. status is "scored" | "skipped" |
// "error"; mode is "relative" | "absolute" for benchmark checks (else empty).
message AuditCheck {
  string id = 1;
  double score = 2;
  string status = 3;
  string raw_value = 4;
  string notes = 5;
  string mode = 6;

// AuditRecommendation is a lowest-scoring check surfaced by global weighted
// impact (check_weight × signal_weight × composite_weight), so the biggest

message AuditRecommendation {

  double score = 2;

message RunAuditRequest {
