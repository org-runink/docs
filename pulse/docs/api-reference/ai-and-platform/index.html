AI and platform

AI and platform

Model access, the agent-activity feed, sign-in, the business profile and self-healing status. Package pulse.v1; the least role of each method is in its table.

Notes

  • ModelService is the door to the platform's own inference plane. There is no third-party model behind it.
  • ActivityService. A subscriber receives only its own runs; a run no account started (a schedule, an inbound message) reaches nobody. Render nothing for an unknown non-empty AgentStep.code, never the raw token; an empty code is valid, so fall back to thought and action. See Agent activity.
  • IdentityService. expires_in is in seconds. Refresh, Google sign-in and sign-out are plain HTTP; see HTTP endpoints.

ActivityService

ActivityService shows what the CALLER's agents are doing right now, across every page and tab, not only the one that started them.

A caller receives only runs started by their own authenticated identity. Runs with no owner (for example scheduled work) are delivered to nobody. The session field is a filter within the caller's own runs, never authorisation.

  AGENT_RUN_STATUS_RUNNING = 1;
  AGENT_RUN_STATUS_DONE = 2;
  AGENT_RUN_STATUS_FAILED = 3;

// AgentStep is one unit of agent work.
//
// `thought` is often empty: a renderer must not assume every step narrates
// itself.
message AgentStep {
  string run_id = 1;
  int32 index = 2;
  string thought = 3;
  string action = 4;
  string input = 5;
  string result = 6;
  string model = 7;
  int64 latency_ms = 8;
  string error = 9;
  int64 at_unix = 10;
  int64 total_tokens = 11;

  // The step's stable, machine-readable kind, for example "STEP_DISPATCHED".
  // Use it, not a sentence, to word the step in the client's own language.
  //
  // Empty is valid: a renderer falls back to thought/action. An unknown
  // non-empty code must render nothing, never the raw token.
  string code = 12;

  // The facts the code declares, as strings. A missing operand should degrade
  // the rendered line, never drop the step. Some values are data (a quoted
  // example, a caller's URL, the model's own words): show them verbatim and
  // never translate them.
  map<string, string> operands = 13;

  // How the answer this step reports was produced. Absent when the step has
  // none. A fresh answer needs no mention; a reused, offline or degraded
  // answer is worth showing.
  StepProvenance provenance = 14;
}

// StepProvenance says how a step's answer was obtained.
message StepProvenance {
  // How it was obtained: "fresh" | "exact-cache" | "near-dup" | "offline".
  // Unknown values must degrade to "no claim", never render raw.
  string source = 1;
  // Diagnostic detail for a tooltip; never the primary label.
  string path = 2;
  // Produced without full capability. A reader should weight it lower.
  bool degraded = 3;
  // When the underlying value was produced. For a REUSED result this is the
  // ORIGINAL computation time. Zero means unknown, not "now".
  int64 computed_at_unix = 4;
}

message AgentRun {
  string run_id = 1;
  // The agent's id, e.g. "pulse:whitepaper".
  string agent = 2;
  string session = 3;
  int64 started_unix = 4;
  // Zero while the run is still in flight.
  int64 ended_unix = 5;
  AgentRunStatus status = 6;
  int32 step_count = 7;
  // Populated only on the initial replay, bounded by replay_steps_per_run.
  repeated AgentStep steps = 8;
  string error = 9;
}

message SubscribeAgentActivityResponse {

    // arrives.
    bool snapshot_complete = 2;
    AgentRun run_started = 3;
    AgentStep step = 4;
    AgentRun run_finished = 5;
  }
}

WeeklyLoopsService

THE WEEKLY LOOPS (owner goal, 2026-11-23: close the autonomy gaps of "agency in an app"). Two weekly loops PROPOSE and a person decides; nothing goes outward and nothing changes by itself: results-to-plan: reads what the account's published and approved work achieved (attribution per channel and campaign, post results, replies) and drafts a PLAN UPDATE: which actions of the 90-day plan to keep, stop or move, each tied to the measured evidence it came from. Too little data = no proposal, with the reason in plain words. site re-audit: re-scores the account's own site (the pipeline's score-only audit) and drafts a REPORT of what improved and regressed against the previous audit; a check nobody measured stays "not measured". Both are per-account switches, default OFF. A proposal waits in the plan screen; approving it applies exactly the edits it lists to the plan (as the person's own edits; a re-audit report is only marked reviewed), rejecting it changes nothing.
