Developer guide

Developer guide

This guide is for developers building on Runink PULSE: Prescriptive Unified Lead & Social Engine: its API and its extension points.

  • Calling the API: grpcurl, bearer tokens, streaming, gRPC-Web, and A2A.
  • API reference: Every service, method, message and least role, generated from the protos.

Architecture in one paragraph

A Go gRPC backend and a Flutter app for Android (iOS is planned and not yet built) talk over gRPC on one port. The backend keeps all its data (every table, account, session and media file) in a sealed store on the platform's object store; there is no database, and one writer, so one instance. All AI is the platform's own, with no third-party model. Runink's TIDDE platform deploys and runs the instance. See Architecture.

What you can build on

Extension point What it is Where
The gRPC API Every service the app uses, with each method's least role. Native gRPC, or gRPC-Web from an allowed origin. Calling the API, API reference
Agent-to-agent (A2A) Another agent calls PULSE's skills over the platform's agent protocol. A2A
Website form endpoint Your site posts contact-form enquiries straight to Leads. Website form, HTTP endpoints
Website chat widget One script tag on your site; a public, origin-pinned site key. Website chat
Connections HubSpot, Google Analytics, Search Console, Google Ads, a website repository and others, each with the customer's own grant. Connections
Content skills Each content type is a skill with its own instructions and checks. Skills ship with PULSE; they are not customer plug-ins yet. Studio

The data model is the set of messages in the API reference and Common types.
