      Telephony and messaging

      Telephony and messaging

      PULSE has four voice and messaging paths. All of them are off until you configure them.

      The carrier settings themselves are admin-only, and they live on the Account page under Messaging & calls — not in the navigation rail. Someone who is not an admin of this instance never sees the carrier fields.

      Outbound calls to leads (Asterisk)

      Leads → Call (LeadService.CallLead) places a real phone call through a self-hosted Asterisk PBX. There is no per-minute calling SaaS.

      1. PULSE asks Asterisk’s REST interface (ARI) to dial the lead into a dialplan context.
      2. That context runs AudioSocket() back to PULSE’s audio listener, passing the call’s ID: AudioSocket(${PULSE_CALL_ID},<pulse-host>:<audio-port>), where <audio-port> is the port in AUDIOSOCKET_ADDR. PULSE sets PULSE_CALL_ID on every call it places. The ID is how a call finds its own cold-call script; without it the call runs with no script.
      3. PULSE transcribes the caller (Voxtral), answers with the sales agent, speaks the reply (Runink TIDE’s shared ttsd, TTSD_URL), and streams it back.
      VariableMeaning
      AUDIOSOCKET_ADDRThe TCP listener Asterisk connects to
      ASTERISK_ARI_URL, ASTERISK_ARI_USER, ASTERISK_ARI_PASSWORDARI access. Leave empty to keep outbound calls off.
      PULSE_OUTBOUND_CALLSMust be true (or another yes) for CallLead to dial. Off by default. Only editors and admins may place calls.
      ASTERISK_ENDPOINT_PATTERNThe dial string, with {number} substituted
      ASTERISK_CONTEXT, ASTERISK_EXTENSIONThe dialplan target that runs AudioSocket()
      ASTERISK_CALLER_IDOutbound caller ID

      If ARI is configured and the audio listener cannot bind, the server refuses to start. Otherwise it would place calls it cannot carry: the lead would answer to silence. When ARI is not configured, a failed bind is only a warning.

      Without ARI, CallLead returns outbound calling isn't configured — set up Asterisk and ..., naming the missing variables.

      Outbound cold calling is regulated. Consent, calling hours, do-not-call lists, and recording disclosure are the operator’s responsibility.

      Browser voice calls

      The app’s full-screen call view sends a WebRTC offer to /voice/webrtc/offer. PULSE forwards it to the platform’s shared calling agent at CALLING_AGENT_URL, which carries the audio. PULSE is only the authenticated signaling door.

      When CALLING_AGENT_URL is unset, the offer is refused with HTTP 503 and voice calling is not configured: CALLING_AGENT_URL is unset. For signaling tests, PULSE_WEBRTC_SIGNALING_ONLY=true answers offers with PULSE’s local handler, which carries no audio.

      Turn-based voice input (/voice/transcribe) needs only the Voxtral server (VOXTRAL_REMOTE_URL). Both voice endpoints require a signed-in caller.

      WhatsApp and SMS

      PULSE accepts inbound WhatsApp and SMS messages from Twilio at /twilio/message, and answers with its marketing personas: the same set it offers over A2A.

      • Every request must carry a valid Twilio signature (TWILIO_AUTH_TOKEN).
      • Only senders who are contacts in PULSE’s HubSpot account may talk to it. PULSE_WHATSAPP_USER_ID picks whose HubSpot connection is used. The default is to deny.
      • The edge generates text: analysis, content, strategy, research. Creating leads or campaigns and approving content stay behind the signed-in gRPC API.
      • Replies are automatic and on by default. Each one passes PULSE’s guardrails, and the incoming message is treated as data, never as instructions. Replies run as the user set in PULSE_WHATSAPP_USER_ID; with none set, nothing is answered.
      • To turn automatic replies off, set PULSE_WHATSAPP_AUTOREPLY=false. Messages are then received but not answered.
      VariableMeaning
      TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKENThe Twilio account
      TWILIO_WHATSAPP_FROM, TWILIO_FROM_NUMBERThe WhatsApp sender and the SMS number
      PULSE_WHATSAPP_USER_IDThe user whose HubSpot contacts form the allowlist, and as whom replies run
      PULSE_WHATSAPP_AUTOREPLYfalse turns automatic replies off. Default: on

      Send / Call to a saved contact

      PULSE also carries the shared Runink Send / Call layer, the same code FACE and TIDE use, so the allowlist, the per-send confirmation, the rate limit, the body cap, the recording notice and the audit trail behave identically across the three.

      • Only a saved contact can be reached. Admins add contacts on Account → Messaging & calls; a number that is not on the list is refused. A service account can never message or call anyone.
      • The carrier settings are sealed with CORE_ENVELOPE_KEK. Without that key the page refuses to store a secret rather than writing it in the clear. Contacts, sealed settings and the delivery trail live under $PULSE_DATA_DIR/comms.
      • Variables. TWILIO_ACCOUNT_SID and TWILIO_AUTH_TOKEN come from the secret store (with an environment fallback); TWILIO_WHATSAPP_FROM, TWILIO_FROM_NUMBER and TWILIO_VOICE_FROM are settings. TWILIO_VOICE_FROM is optional and falls back to TWILIO_FROM_NUMBER. What an admin saves on the page overlays the environment.
      • Delivery states are posted back to /comms/twilio/status. Without PULSE_PUBLIC_BASE_URL there is no callback URL to give the carrier, so states stay at accepted.
      • A call speaks and ends. It plays the recording notice first, then PULSE’s greeting and the summary; there is no interactive media leg on this path.
