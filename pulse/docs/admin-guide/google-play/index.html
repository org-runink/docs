      Google Play release

      PULSE ships to phones through Google Play only, published by the Runink organization developer account (one account for every Runink app). This page lists every step from source to the internal testing track. Each step says whether the code does it (code, with where) or the owner does it (owner). Sources, read 2026-11-02:

      • Publish your app and Sign your app
      • Target API level requirements: from 2026-08-31, new apps and app updates must target Android 16 (API 36) or higher. The extension Google offered ran to 2026-11-01 and has passed.
      • Account deletion requirements
      • Graphic assets

      Build the bundle:

      cd flutter
flutter build appbundle --release --obfuscate \
  --split-debug-info=$HOME/.cache/pulse-android-symbols/$(git rev-parse --short HEAD) \
  --dart-define=PULSE_BACKEND_URL=https://<the public PULSE host>

      Without PULSE_BACKEND_URL the app talks to http://localhost:50051 and cannot reach PULSE from a phone; the build warns. Keep the symbols directory: flutter symbolize needs it to read a crash trace. The Build Android App Bundle workflow (manual) does the same and keeps the unsigned bundle and the symbols as private workflow artifacts; it publishes nothing.

      2. Signing: owner, no secret in any repository

      Play App Signing: Google holds the app signing key; the owner holds an upload key outside every repository and CI system.

      1. owner, once: create the upload key (Play needs validity past 2033-10-22):

        mkdir -p ~/.config/runink/android && chmod 700 ~/.config/runink/android
keytool -genkeypair -v -keystore ~/.config/runink/android/pulse-upload.jks \
  -storetype PKCS12 -alias pulse-upload -keyalg RSA -keysize 4096 \
  -validity 10000 -dname "CN=PULSE upload, O=Runink"

        Keep the keystore and its password in the owner’s password manager. If it is lost, Play Console can reset the upload key; the app signing key is not affected.

      2. owner, each release, either way:

        • sign the unsigned bundle: jarsigner -keystore ~/.config/runink/android/pulse-upload.jks app-release.aab pulse-upload; or
        • build signed: copy flutter/android/key.properties.example to ~/.config/runink/android/pulse-key.properties (chmod 600), fill it in, and add -PpulseKeyProperties=$HOME/.config/runink/android/pulse-key.properties (or set PULSE_ANDROID_KEY_PROPERTIES) to the build.

        With no key given the build says UNSIGNED and produces an unsigned bundle, which Play will not accept until it is signed.

      4. Open decisions: owner

      • Payments. The Android app never sells. It is built with --dart-define=PLAY_STORE_BUILD=true (.github/workflows/build-android.yml, checked by grpc/cmd/android_release_test.go), and in that build the shared Subscription page shows the plan, seats and usage only: no list prices, plan picker, checkout, estimate or billing-portal link, and a note that the organisation’s administrator chooses the plan. Seats are bought on the web. Choose before changing that: Google Play Billing (not built) or one of Play’s external-offers programmes.
      • The public backend host. https://pulse.runink.org answers browsers. The Android app speaks native gRPC, which reaches PULSE only once TIDE’s edge passes application/grpc through over HTTP/2 (in progress); until then every call from the app fails. Build with backend_url=https://pulse.runink.org once that is live.
      • privacy@runink.org must be a monitored mailbox: the web deletion route names it.

      5. Account deletion: what the code does

      IdentityService.DeleteAccount (grpc/cmd/delete_account.go) checks the typed email, refuses the break-glass admin and the only admin, ends every session of the account, then deletes in one transaction every row whose user_id is the account’s, the rows of its audit runs, and the users row (grpc/internal/db/delete_account.go). Not reached yet: rows linked to the account only through another parent id, sealed media in the file store, and the Litestream replica’s history, which keeps old copies until its retention removes them.
