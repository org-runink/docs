First response to enquiries

First response to enquiries

First response lets an account's PULSE acknowledge a new website enquiry (see the user guide). This page is what an administrator needs: the switches, the order to arm them, and every gate.

Defaults

Setting Where Default
First response Settings › Account, per account off
Send acknowledgements automatically Settings › Account, per account off
First response wording Settings › Account, per account empty (a neutral sentence)
Unanswered threshold (hours) Settings › Account, per account unset (count with no threshold)
PULSE_RESPONSE_TIME_WINDOW_DAYS, PULSE_RESPONSE_TIME_MIN_LEADS server unset

Only an editor or an administrator, in their own session, changes the switches.

Arming order

  1. The global kill switch PULSE_APPLY_ENABLED and the email channel switch PULSE_PUBLISH_EMAIL (see Switches and arming order).
  2. PULSE_PUBLIC_BASE_URL must be an https address: the unsubscribe link is built from it.
  3. A connected mailbox, and the account's Outreach sender name and postal address.
  4. The account turns on First response. From that moment, new enquiries get a draft. Nothing is sent without a tap. Enquiries from before that moment are never looked at.
  5. Only then, if the account wants it, Send acknowledgements automatically. It applies to enquiries received after it was switched on.

If the sender name, the postal address or the https address is missing, nothing happens and Settings lists exactly what is missing.

Every gate, in order

For each new enquiry from the website form: the feature is on; the sender name, postal address and https address are present; the enquiry arrived after the feature was switched on; the address is a business address, not suppressed, not the account's own, not a customer's, not already contacted; the acknowledgement is composed from a Go template (no model call); a draft is stored (loop first-response, Allow("save first response draft")).

An automatic send additionally passes, in the one function deliver: the account's working hours and daily cap; the loop gate (Allow("send first response")); the outreach footer and its compliance check; OpenBias on the text; My rules and the conscience gate, acting as the role pack partnerships-agent (contact hours 9-18, ten a day, no first-contact approval of its own; the account's own rules still apply); the shared mail service (the kill switch, PULSE_PUBLISH_EMAIL, the mailbox limit). A person's Send runs the same function as that person; a warning is confirmed with Send anyway, and a block stays a draft.

The record is claimed before the send, so one lead gets at most one acknowledgement ever. The unsubscribe link (/first-response/unsubscribe/<token>, public like the website form's route) puts the address on the account's suppression list.

What is kept

Per lead: the arrival time, the state, a reason code, and, while it is a draft or after it was sent, the address and the text, sealed. The enquiry's own text is never stored by this feature. The records are removed with the account and are part of the Leads area of Export my data.

Response time

The card needs a window and a minimum, set on the server:

Variable Meaning
PULSE_RESPONSE_TIME_WINDOW_DAYS Days of enquiries the median and the 90th percentile cover.
PULSE_RESPONSE_TIME_MIN_LEADS The fewest answered leads before a figure is shown.

Either unset, or fewer answered leads than the minimum: the card says Not measured and why. It is never shown as zero.

Automations

The automation triggers trigger.form_submitted, trigger.reply_received, trigger.engagement_received, trigger.meeting_detected and trigger.lead_scored start flows from the same events. They carry ids and codes only. See Automations.
