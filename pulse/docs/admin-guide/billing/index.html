      Billing

      System → Billing (/billing) is the shared Runink Billing page from org-runink/ui. PULSE serves its API, runink.ui.billing.v1.BillingService, over the org-runink/billing library, with PULSE-specific hooks. The page lists and prices PULSE’s own plans, never another product’s. For the plans, prices, and the Lite daily task limit, see Plans.

      Where the subscription comes from

      PULSE runs one deployment per tenant. The subscription is read from environment variables that Runink TIDE’s operator projects onto the pod:

      VariableMeaningWhen missing
      TENANT_IDThe tenantNo subscription on record
      SUBSCRIPTION_TIERThe plan tier: lite, dedicated, or enterpriselite
      SUBSCRIPTION_SEATSNumber of seats1
      SUBSCRIPTION_STATUSSubscription statusactive
      SUBSCRIPTION_PERIOD_ENDEnd of the current billing period (RFC 3339)No period shown
      SUBSCRIPTION_ANNUALtrue for a yearly subscriptionMonth-to-month

      The tier, seat, and status defaults apply only when TENANT_ID is set. Without TENANT_ID, the page shows that no subscription is on record. It does not invent a Lite plan. An unknown tier is never treated as Lite: the subscription is shown as suspended.

      The page derives the current period from SUBSCRIPTION_PERIOD_END, running from your subscription’s anniversary date. With no period on record, it shows no period and prices the month-to-month rate. A Dedicated plan is sold yearly only.

      Several purchasers on one instance

      On an instance shared by several customers, RUNINK_ACCOUNTS_FILE (the member-to-purchaser file TIDE’s operator projects) maps each signed-in person to the purchaser who pays for their seat. A purchaser’s own row sets their plan and seats, so a Lite purchaser’s seats get the daily task limit and a Dedicated or Enterprise purchaser’s do not. People with no row fall back to the instance’s SUBSCRIPTION_* variables.

      Where the daily task count is kept

      The Lite daily task count lives in the usage bucket TIDE’s operator gives the pod (RUNINK_USAGE_*), as append-only records. When a deployment has no usage bucket, as in local development, tasks are not counted and the page says that daily usage is not tracked on this deployment.

      What each part of the page does

      FeatureIn PULSE
      Plan catalog and price quotes (ListPlans, QuotePlan)Work. Pricing is arithmetic, done on the server, from PULSE’s catalogue.
      Overview of your subscription (GetOverview)Works, from the variables above.
      TodayOn Lite, “Today: X of 10 fast tasks” for the viewer’s seat, and the reset time once the limit is reached. Dedicated and Enterprise show no daily count.
      EstimateEvery line is either computed or says why it cannot be.
      CurrencyThe page shows US-dollar list prices and says so. Invoices are in your regional currency; see Currency and billing periods.
      Checkout and the billing portal (StartCheckout, OpenPortal)Subscriptions are bought through Runink, so both answer “not configured” and nothing on this page can charge.
      Seats (ListSeats, AssignSeat, RevokeSeat)Seats come from the subscription; the page shows no seats section.

      Billing actions are logged to the process log as billing audit lines.

      The deprecated MeteringService

      pulse.v1.MeteringService is a deprecated alias. PULSE is billed per seat, so it reports the subscription and no compute figures:

      • GetComputeBudget returns the tier, the seats, the per-seat price, and the annual flag. The compute-unit fields are always unset.
      • GetResourceUsage answers UNIMPLEMENTED: compute-unit consumption is not metered by PULSE; see runink.ui.billing.v1.BillingService/GetOverview.
      • SetComputeBudget answers UNIMPLEMENTED: PULSE is billed per seat and has no compute budget to set.
      • Without a subscription on record, the reads answer FAILED_PRECONDITION: no subscription is on record for this deployment (TENANT_ID is not projected).

      New clients should call runink.ui.billing.v1.BillingService/GetOverview.
