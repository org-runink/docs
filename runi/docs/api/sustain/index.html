      runi/sustain

      runi/sustain

      import "github.com/org-runink/runi/sustain"

      Package sustain keeps a decision made on a noisy series from flapping around its threshold.

      A check of the form “x > limit” run on every reading of a live series changes its answer every time noise carries x across the limit, and whatever the answer drives — an alert, a throttle, a scale-up — changes with it. The remedies are old and well understood: two levels instead of one, a condition that must persist before it counts, a majority over the last few readings, a bound on how fast an output may move. This package provides each as a small value type that takes one reading at a time, with the time the reading was taken.

      Which to use:

      • Hysteresis is an on/off state with a set level and a separate clear level (a Schmitt trigger), High or Low, and an optional minimum dwell in a state after each change. The deadband between the levels absorbs noise smaller than itself.
      • Debounce follows a boolean condition only after it has held for a time and/or a number of consecutive readings, with separate delays for on and off: the on-delay and off-delay of alarm management.
      • NofM is on while at least Need of the last Size readings (Size ≤ 64) are past a level: it escalates on a condition that holds most of the time, which a Debounce would keep restarting.
      • Band classifies a reading into ordered levels — below, inside, above; normal, warning, critical — with a deadband on every edge.
      • Slew bounds how fast an output follows its input, in units per second of the readings’ own time, with separate rates up and down.

      They compose. Debounce takes any condition, so a Hysteresis’s state or a Band’s level compared with a constant can feed it; a Slew in front of any of them smooths what they see, and one behind a controller smooths what it does.

      h, _ := sustain.NewHysteresis(sustain.High, 90, 80, time.Minute) d, _ := sustain.NewDebounce(sustain.Delay{For: 30 * time.Second}, sustain.Delay{}) for r := range readings { if d.Update(h.Update(r.Value, r.At), r.At) { log.Printf(“hot for %v”, d.InState(r.At)) } }

      Time comes only from the at argument of each Update; nothing here reads the clock or sleeps, so every type is as testable as the caller’s clock is. Times are compared with time.Time.After and differenced with time.Time.Sub, which use the monotonic reading time.Now attaches, so a wall-clock step between two such readings does not distort an interval.

      Two rules hold for every type, and tests hold each type to them:

      • A reading whose time is not after the last accepted reading — a duplicate, a clock stepped back, readings delivered out of order — is skipped. There is no right place to put a late reading in a state machine that has already acted on later ones, and a duplicate would count twice toward a number of readings.
      • A NaN or ±Inf reading is skipped. A missed reading should not decide a state, and “no reading” is not evidence for either side of a level.

      A skipped reading is counted in Skipped and leaves no other trace: the state, the time of the last reading and any run or window are exactly as if it had never been offered. A series that is mostly skipped readings is visible as one.

      Every Update does O(1) work in fixed memory — Band’s is O(levels crossed) — and allocates nothing; a test holds each to zero. Every type is safe to copy and none is safe for concurrent use; give each goroutine its own, or guard it. Constructor errors wrap ErrInvalid.

      What this package does not do

      It does not choose levels, deadbands or delays. Those depend on the series’ noise and on what a late or a false decision costs, which only the caller knows. ISA-18.2 and its technical report on alarm design tabulate starting deadbands and delays by measurement type for process plant signals; a deadband a few times the noise’s standard deviation, measured over a stretch known to be normal (Welford in github.com/org-runink/runi/drift), is the usual first try elsewhere.

      It does not detect change. A deadband stops flapping around a level you chose; whether the series’ level has itself moved is a question for the detectors in github.com/org-runink/runi/drift, whose output can then drive a Debounce here.

      It sees only readings. A Debounce’s “held for 30 s” is “every reading for 30 s agreed”; a gap between readings is not seen, so a run of two readings a minute apart has lasted a minute. A caller who needs to treat a long gap as breaking a run should check it (Intervals in github.com/org-runink/runi/rate watches gaps) and call Reset.

      It does not reorder or interpolate. A late reading is dropped, not placed; a Slew’s output exists only at readings, and nothing between them is computed.

      It never acts. Nothing here alerts, throttles or retries; each type returns a state or a number, and what follows from it is the caller’s.

      Band 

      type Band struct

      Band classifies each reading into one of an ordered set of levels — below, inside and above a band; normal, warning and critical — with hysteresis at every boundary.

      The levels are numbered 0 to len(edges), lowest values first, and edge k separates level k from level k+1. Each edge is a Schmitt trigger with its own pair of levels, so a reading that sits near a boundary does not flip between the levels on either side of it: noise whose peak-to-peak amplitude is less than an edge’s Up − Down cannot carry the level across that edge both ways. A reading may move the level several steps at once; a reading strictly between an edge’s Down and Up leaves that edge where it was.

      For a band where the middle is normal, give two edges: level 0 is below, 1 inside, 2 above. For severities that rise with the value, level 0 is normal and each edge is a more severe alarm; for severities that rise as the value falls, number them from the top (severity = len(edges) − level).

      The edges must be in order: both Up and Down strictly increasing from one edge to the next. Then the level is always the number of edges whose trigger is on, as if each edge were a separate Hysteresis, and the tests hold Band to exactly that.

      Dwell is an optional minimum time at a level after a change, as for Hysteresis: a reading less than dwell after the last change cannot move the level, is counted in Held, and is not remembered. It applies only after a change; the first move from level 0 is never delayed. With a dwell, the level is no longer the count of separate triggers, since one change holds back every edge.

      The level starts at 0. NaN and ±Inf readings are skipped, and so are readings whose time is not after the last accepted reading; both are counted in Skipped and leave no other trace.

      Method: the multi-level alarm with a deadband on each setpoint of ANSI/ISA-18.2-2016, Management of Alarm Systems for the Process Industries; each edge is the trigger of O. H. Schmitt, “A thermionic trigger”, Journal of Scientific Instruments 15(1), 1938.

      NewBand copies the edges; Update never changes them, so a copy of a Band shares them safely and is independent of the original. The zero value has no edges and is always at level 0; build one with NewBand. Not safe for concurrent use.

      Defined in sustain/band.go.

      Debounce 

      type Debounce struct

      Debounce is an on/off state that follows a boolean condition only once the condition has held, continuously, for a set time or number of readings.

      The condition is anything the caller decides per reading: a value over a level, a check that failed, the output of a Hysteresis. A condition that flickers — true for one reading in a run of false ones — is noise, and Debounce ignores it: the state turns on only after the condition has been true on every reading of a run that satisfies the on Delay, and turns off only after it has been false on every reading of a run that satisfies the off Delay. A single reading that agrees with the current state ends the run and the count starts again. The two delays are separate because the costs are: a late alarm and a late all-clear are different mistakes.

      “Continuously” means as far as the readings show. The time a run has lasted is the time between its first reading and the current one; what happened between two readings is not seen, so a run of two readings an hour apart has lasted an hour.

      Readings whose time is not after the last accepted reading (duplicates, a clock stepped back, readings delivered out of order) are skipped and counted in Skipped; they neither extend nor break a run.

      Method: the on-delay and off-delay timers of ANSI/ISA-18.2-2016, Management of Alarm Systems for the Process Industries, where an alarm is annunciated only after its condition has persisted for the on-delay and returns to normal only after the return has persisted for the off-delay. The count of consecutive readings is the sampled form of the same rule, the integrating debouncer of switch-input practice.

      The zero value is a Debounce with no delays, ready to use: it follows its condition at every reading. Safe to copy, not safe for concurrent use.

      Defined in sustain/debounce.go.

      Delay 

      type Delay struct

      Delay is how long a condition must hold before a Debounce follows it: for at least For, measured from the first reading of the run to the current one, and over at least Readings consecutive readings. Both must be met when both are set. The zero Delay is no delay: the state follows at the first reading. Readings of 0 and 1 are the same requirement.

      Defined in sustain/debounce.go.

      type Edge struct

      Hysteresis 

      type Hysteresis struct

      Hysteresis is an on/off state with separate levels for turning on and turning off: a Schmitt trigger.

      A single threshold under noise flaps: a reading that sits near it crosses it on every other sample, and every crossing is a change of state. Two levels stop that. For a High alarm the state turns on at a reading at or above set, and turns off only at a reading at or below clear, with clear < set. Readings strictly between the two change nothing. The gap set − clear is the deadband, in the data’s units: noise whose peak-to-peak amplitude is less than the deadband cannot carry a reading from one level to the other, so it can cause at most one change, never a flap. Low is the mirror image: on at or below set, off at or above clear, with set < clear.

      Dwell is an optional minimum time in a state after a change, the minimum on-time and off-time of relay and thermostat practice. A reading less than dwell after the last change cannot change the state again; it is counted in Held. It is not remembered either: once the dwell has passed, the state changes at the first reading that is itself past the opposite level. The dwell guards against a fast series that is truly crossing both levels (a deadband narrower than the swings), which no deadband alone can stop. It applies only after a change: the first change, from the initial off state, is never delayed.

      The state starts off. The first reading is judged like any other, so a series that starts at or past set turns the state on at once.

      NaN and ±Inf readings are skipped, and so are readings whose time is not after the last accepted reading (duplicates, a clock stepped back, readings delivered out of order); both are counted in Skipped and leave no other trace.

      Method: O. H. Schmitt, “A thermionic trigger”, Journal of Scientific Instruments 15(1), 1938. The deadband as an alarm setting: ANSI/ISA-18.2-2016, Management of Alarm Systems for the Process Industries, where it is the distance a signal must move back past the setpoint before the alarm returns to normal (clear = set − deadband for a high alarm).

      The zero value is not usable; build one with NewHysteresis. Safe to copy, not safe for concurrent use.

      Defined in sustain/hysteresis.go.

      NofM 

      type NofM struct

      NofM is on while at least Need of the last Size readings are past a level: the N of M of its name.

      It sits between a plain threshold, which fires on one reading, and a Debounce, which needs every reading of a run: a condition that holds most of the time but not always — three readings over in five, with one dip back under between them — escalates here and would keep restarting a Debounce. For a High level a reading is past it when it is at or above it; for Low, at or below.

      The last Size outcomes are kept as bits of one word, newest in the lowest bit, so an update is a shift, a mask and a population count: no buffer and no allocation, and the count is exact. Before Size readings have been accepted the window holds those there are, and Need of them suffice. NofM has no deadband of its own; the window is its smoothing.

      NaN and ±Inf readings are skipped and take no slot, so “the last Size” means the last Size finite readings. Readings whose time is not after the last accepted reading are skipped too. Both are counted in Skipped.

      Method: the M-of-N rule is the “binary integration” (double-threshold) detector of radar, M. I. Skolnik, Introduction to Radar Systems, McGraw-Hill; the same rule over a control chart’s zones gives the run rules of the Western Electric Statistical Quality Control Handbook, 1956 (“two out of three beyond two sigma”, “four out of five beyond one sigma”), as tabulated in D. C. Montgomery, Introduction to Statistical Quality Control, Wiley.

      The zero value is not usable; build one with NewNofM. Safe to copy, not safe for concurrent use.

      Defined in sustain/nofm.go.

      Slew 

      type Slew struct

      Slew is a rate limiter: its output moves toward its input, but by no more than a set amount per second of the readings’ own time.

      A setpoint or a control output that jumps — a limit cut in half in one step, a replica count that doubles — can do more harm by the jump than by the new value. Slew passes the input through, but bounds how fast the output may follow: over an interval of Δt seconds between readings it rises by at most rise·Δt and falls by at most fall·Δt, and it never passes the input. A step in the input becomes a ramp; an input that stays within reach is followed exactly. Separate rates for rising and falling allow the usual asymmetric forms, such as fast to back off and slow to return; either may be +Inf, which removes the limit in that direction.

      The bound is on the readings’ timestamps, not on the number of readings: readings close together move the output a little each, readings far apart a lot. The first reading sets the output to the input, since there is no earlier output to limit. The arithmetic is the bound itself: when limited, the output is exactly old ± rate·Δt as one floating-point addition rounds it, so it never moves farther than that rounded sum. A step smaller than the spacing of floating-point numbers at the output’s magnitude rounds to no movement at all.

      NaN and ±Inf readings are skipped, and so are readings whose time is not after the last accepted reading; both are counted in Skipped and leave no other trace. The next accepted reading’s Δt then covers the skipped interval, so the output may make up the movement it was allowed then.

      Method: the rate limiter of control engineering, the nonlinear element that bounds the derivative of a signal, treated among the actuator limitations that cause integrator windup in K. J. Åström and T. Hägglund, Advanced PID Control, ISA, 2006; here in sampled form, with the bound taken over each irregular interval.

      The zero value is not usable; build one with NewSlew. Safe to copy, not safe for concurrent use.

      Defined in sustain/slew.go.
