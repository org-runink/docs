      Judgements

      A judgement is Runink TIDE’s independent verdict on a finding that an external assessment platform submitted. The judge agent makes it and lands it on the finding in the console’s store. The page is DataEx › Judgements (?tab=judgements).

      The docket starts empty. CORE_JUDGEMENT_INGEST_TOKEN gates POST /api/judgement/submissions, and while it is unset the endpoint refuses everything. An admin issues it when an external assessment platform is onboarded. Until then the judge reports unable-to-judge, with that reason. That is the design working, not a bug.

      One document, three routes

      The console owns the shape: a store with version, revision, updatedAt, submitters{} and judgeRuns[]. Its source of truth is the console’s own table, and the copy the agent reads is rewritten after every change, so make changes in the console. The agent reads that copy and defines nothing.

      The routes are split by authority, never by a field in the body:

      RouteMethodAuthorityWhat it does
      /api/judgement[?submitter=NAME][&batch=ID]GETbrowser sessionthe submitted findings and TIDE’s verdicts on them. Answers 200 even when the store is unreadable, and says so in the body
      /api/judgement/submissionsPOSTthe submitter’s shared CORE_JUDGEMENT_INGEST_TOKEN as a bearerfindings in. Any verdict on the wire is discarded, because a platform may not grade its own work. The response is the stored, judged batch. Re-posting the same batchId is idempotent. The body limit is 1 MiB
      /api/judgementsPOSTthe GitHub App’s rights for the console’s org (authorizeReporter)verdicts in, from TIDE’s own judge agent. This is the only way a verdict enters the store
      /api/judgementsGETbrowser sessionthe judge agent’s runs

      The ingest token is refused by name at the judge’s door: “the submission ingest token has no authority here: a platform that submits findings does not judge them.”

      Outcomes

      concur, dissent or unable-to-judge (the console also accepts its own out-of-scope). Anything else is refused at the door. Unable-to-judge is never rendered as agreement. When the judge cannot reach a verdict it abstains, with the reason.

      Deterministic checks run before any model call. A quantitative claim is settled by arithmetic over the evidence’s own numbers, never by a model, and a claim the evidence contradicts is a dissent. The model sees only what arithmetic cannot settle, and is never told the submitter’s stance. How the judge weighs evidence beyond that is deliberately not published: a public description of exactly what passes would be a recipe for submissions written to pass it.

      Every verdict carries a stable reason code. Two of them matter operationally:

      • blocked-by-guard is a block, not an outage. The guardrails withheld the claim or the model’s answer, so a person reviews it. The judge reports it in its own “Blocked by guard” section, never retries it and never counts it as agreement.
      • model-unavailable is the only retryable reason: a later run may judge that submission again.

      The fast path

      Before its LLM call, the judge may answer with a small pinned tree model, switched by the Actions variable CORE_FAST_JUDGEMENT (default on). It answers only the clear cases, and never without evidence. Whatever it does not answer goes to the LLM exactly as before. Every model-based verdict records which path it took, for example basis: model (fast-model judgement-fast v0 sha256:…) or model (llm).

      When the judge runs

      • daily at 08:29 UTC;
      • on an @core_judgement comment;
      • on a manual run;
      • as a playbook step.

      It writes to two sinks: the console store and the living “⚖️ Judgement status” issue. A successful store write raises the harness event judgements.reported (dissent, unable).

      Not the same as

      • eval’s judge scores our own agents’ run traces 0..1 against a golden set. judge assesses somebody else’s finding against its evidence.
      • The plan gate in fixer, selfheal and triage runs the same checks over each agent’s own proposal before it acts.
