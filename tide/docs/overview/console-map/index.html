      Console map

      This page lists every row on the console rail, in rail order, with its link name and what it reads.

      • The structure is defined in one place, flutter/lib/core/widgets/nav.dart.
      • It is pinned by flutter/test/nav_ia_test.dart.
      • The labels come from flutter/lib/l10n/app_en.arb.

      Link to any page with ?tab=<name>, for example https://<your console>/?tab=runners. Names are case-insensitive. An unknown name opens Overview.

      On 2026-09-28 the rail was reduced twice, both times with the owner’s approval:

      • The consolidation took it from 44 rows to 29.
      • The nav cut took it from 29 rows to 16, and moved Admin to the footer.

      Each time, a page that was a second view of one subject became a sub-tab, persona or panel of the page that owns that subject. Every old ?tab= name still works and opens the exact view. See Link names that still work.

      Overview

      Row?tab=Reads

      Overview carries the audit verdict strip: the Platform audit, Model & agent audit and Data audit verdicts, side by side. Each has a Details button that opens the full audit, with every check, its actions and its history. See The audits.

      Intelligence

      The Atlas pages are a page-for-page Flutter port of the partner product Atlas (flutter/lib/features/intelligence/ATLAS_SOURCE.md). They read the console’s in-process gRPC-web services. See the Intelligence API reference for every RPC.

      Row?tab=Sub-tabs, in orderReads

      EstateresolveResolve · Lineage (lineage)the shared estate service (runink.ui.estate.v1.EstateService); /api/data-lineage, /api/data-governance-findings

      Overview reads:

      • CapexService.ListScanRuns, /api/governance-runs and /api/rules-recon;
      • CapexService.GetAnalystDashboard and GetCfoDashboard;
      • /api/data-governance-findings, /api/measures, /api/finops, /api/compliance and /api/maturity.

      Settings is not a row. It is the gear at the end of the Overview tab strip, and ?tab=settings opens it: WorkspaceService, /api/github and /api/rules-recon. While onboarding is not complete, the strip also shows a Set up Intelligence button that opens the same panel.

      Estate asks where each action runs. Test, Explore, Access patterns and Map estate each open a confirm dialog that asks where to run:

      • the source’s own runner (the default);
      • Runink managed;
      • one of your registered self-hosted runners.

      CapEx reads CapexService.GetSummary, GetFeeds, ListFindings, TraceFinding and GetRuleBook.

      • Its import dialog’s Pull from a connection asks where the pull runs, with the same choices as Estate.
      • Its Remediation tab is the remediation queue, GovernanceService: ListRemediations, DryRunRemediation, DecideRemediation and ListDecisions. It then shows /api/compliance per control, and sign-off & audit (/api/agents, /api/governance).

      Business Rules is the shared ui rulesrecon view; /api/rules-recon serves the same view as JSON. Its governance section calls GovernanceService: ListRuleChanges, ProposeRuleChange, DecideRuleChange and SetRuleOwner.

      Playbooks (it was called Orchestrator) links to Agent runs › Schedules & arming for the schedules that run outside any playbook.

      Footer

      • The instance row names the instance the console acts for, and your role on it. Choosing it reopens the instance cards.

      • Admin (admin) sits directly under the instance row, and only if you are an admin of that instance. It manages that instance’s members and seats, through the shared access service.

      • Account is the shared profile page. It shows:

        • your sign-in method and session expiry;
        • the instances you hold a live grant on;
        • Runink TIDE’s GitHub configuration, cloud providers and legal sections.

        Billing is its own page, opened from Account.

      A subscriber sees only their home, the instance row, Admin (if they administer the instance) and Account.

      The audits

      Platform audit, Model & agent audit and Data audit are the three tiles of the Overview’s verdict strip. They are assessments, not the audit log (the audit log is DevEx › Audit chain).

      • Each opens on one verdict over checks read from existing endpoints.
      • A check it could not read goes into a “not measured” list with its reason, never into the passes.
      • Agent reviews start only through an existing playbook’s PlaybookService.RunNow, never through a new dispatch path.

      The Data audit’s own actions live on the pages that own them. Test, Explore, Access patterns and Map estate are on Intelligence › Estate, and a CapEx pull is on CapEx. Each asks where it runs. The Data audit panel links to both.
