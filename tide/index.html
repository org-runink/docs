      TIDE Admin & Developer Guide

      Operate the Runink Platform

      TIDE is the shared platform under the Runink applications: the operators and the tenant API on a k0s cluster, the security spine, the sovereign agent fleet, and the console that ties them together.

      Overview
      Sign in, read the Overview page, and learn how the platform is built.
      DevEx
      The core CLI, coding sessions, the agent fleet, CI workflows, and the cluster pages.
      DataEx
      Models and inference, agents, connections and runners, trust, and judgements.
      Intelligence
      The Atlas pages: CapEx governance, Resolve, playbooks, Ask, audits and lineage.
      FORGE
      The FORGE studio inside TIDE, its project manifest, and central verification.

      New to TIDE?

      Start here: Getting started: sign in, choose an instance, and read the Overview page.

      What TIDE is. TIDE holds everything the Runink apps share and must not re-implement: the Kubernetes operators and the ClientInstance tenant API, PKI and mTLS, envelope encryption, the event mesh, inference serving, the edge, and the infrastructure as code. The apps (FACE, PULSE and LUNA) and FORGE’s own service do not import TIDE; code they share lives in shared libraries. FORGE is one of TIDE’s five categories.

      What you can do here:

      • Overview: see whether anything is wrong, and where to go next.
      • DevEx: run the platform with the core CLI, run TIDE’s own coding agent, and follow the thirteen agents/ binaries (seventeen entries on the console roster) through their workflows.
      • DataEx: see which models serve and which agents act, register connections and self-hosted data-access runners, and control who may do what.
      • Intelligence: govern capital spend with the CapEx engine, map the data estate with Resolve, automate with playbooks, and ask grounded questions.
      • FORGE: open FORGE’s chats in the Studio; TIDE verifies every forged repository centrally.

      The five categories

      The documentation follows the console rail, which is Overview · DevEx · DataEx · Intelligence · FORGE.

      CategoryAudienceQuestion it answers
      OvervieweveryoneIs anything wrong, and where do I go next?
      DevExthe people who build and run the platformWhat is deployed, how does traffic reach it, is the audit record intact, and what did the agents do?
      DataExthe people who consume what the platform decidesWhich models serve, which agents act and within what limits, which sources TIDE reads, and who may do what?
      Intelligenceanalysts and data ownersWhat does the platform know about the data estate, and did a commit ship?
      FORGEbuildersWhat is being built on the platform?
