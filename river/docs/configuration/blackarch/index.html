Security tools on the live stick

Security tools on the live stick (BlackArch)

The Runink River live stick has the BlackArch repository configured and signed, so you can try a security tool in the live session. The image installs no tool, and installed systems never have the repository. This page covers listing, searching and installing a tool, and what happens when you install Runink River.

BlackArch is a pacman repository of thousands of penetration-testing and security-research tools. On the live stick of the public Runink River image you can install one with pacman to try it. The live session runs in memory and is gone at power-off.

  • The image installs no BlackArch tool. You choose what to install, one tool at a time.
  • An installed Runink River system never has the repository. The installer leaves out the repository, its keys and its mirror list. It refuses to install while a tool you added in the live session is still installed.

Note: Only use these tools on systems and networks you own or are explicitly authorised to test.

What the stick sets up

A few seconds after the stick boots, it adds this to the end of the live /etc/pacman.conf:

[blackarch]
SigLevel = Required
Usage = All
Include = /etc/pacman.d/blackarch-mirrorlist
  • SigLevel = Required: pacman refuses the repository's database, and any package, unless it is signed by a key BlackArch trusts. Runink River copied the keys from BlackArch's own signed keyring package and checked them against the fingerprints the BlackArch project publishes. The stick does not download or run any setup script.
  • It is the last repository, so a tool never replaces a system package of the same name.
  • /etc/pacman.d/blackarch-mirrorlist lists seven HTTPS mirrors. If one fails, pacman moves to the next.

If it did not work, the log is /run/river-live-blackarch.log.

List and search tools

The live session needs a network connection. Download the package databases first:

sudo pacman -Sy

Then:

pacman -Sl blackarch                 # every package in the repository
pacman -Sg | grep '^blackarch-'      # the categories (blackarch-scanner, blackarch-wireless, ...)
pacman -Sg blackarch-recon           # the tools in one category
pacman -Ss -q '^nmap'                # search by name (all repositories)
pacman -Si <tool>                    # details, dependencies, which repository it comes from

Install a tool

sudo pacman -S <tool>

Install tools one at a time, by name. A category such as blackarch-recon can hold hundreds of packages, and the whole blackarch group thousands. Installing a group pulls in every tool in it and all their dependencies, into the live session's memory.

If pacman asks to replace a system package with a package from blackarch, answer n. The default answer is yes.

Tools and the stick's age

The stick's system packages are fixed at its build date. BlackArch always serves its newest builds and keeps no older versions. Most tools install and run. A tool built after the stick can need a newer library than the stick has:

  • If pacman stops with unable to satisfy dependency, the tool needs a newer stick.
  • If the tool installs but fails with error while loading shared libraries, the same applies.

Installing Runink River afterwards

Installed systems never carry BlackArch. If you installed a tool in the live session, the installer stops and names it. Remove it, then run the installer again:

sudo pacman -Rns <tool>

You can also restart the stick, which discards everything the live session installed.

To use BlackArch on an installed system, you would add the repository yourself. Runink River does not support that: an installed system takes its software only from Runink River's pinned, signed repositories.

For maintainers, docs/BLACKARCH.md covers what ships, how it is kept off installed systems, and how the key was verified.
