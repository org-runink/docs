Models & inference

Models & inference

Everything on the model plane is sovereign: the platform serves its own models, and there is no hosted-model path. The model cards name the open base models in use.

The servers and what they serve are on DEVEX › Clusters (Nodes & servers section).

Tiers

Every request names a tier in its model field: general, coder, guard, reranker, stt, embedding, vision or imagegen. Each tier is served by an inference server outside the cluster or on the cluster itself. When a server cannot be reached, its tiers answer 503 with Retry-After.

Model cards

GET /api/models (session-gated) returns one row per serving tier: the reviewed model card (provenance, licence, intended use, scope, evaluation evidence) and its live state. A tier is healthy only if it is deployed, ready, and running what its card names.

Usage is reported only as far as it exists. Token use comes from the app agents' own reports, and anything nobody exports appears as unmeasured[].

GET /api/inference returns the plane as deployed: engine, model, quantization, context window, requests and limits, live memory and CPU, restarts and last termination. Live usage is absent, not zero, when no metrics source is available.

Calling the plane

Callers use one OpenAI-compatible front door. What a caller can rely on:

  • Work waits rather than fails. When the plane is busy a request queues. When it cannot be served in time, it answers 503 with Retry-After.
  • A caller that leaves takes its work with it. The slot is freed for someone still waiting.
  • A caller can say how long it will wait, and work is never queued past that deadline.
  • People are served ahead of background work. A request made for a person waiting in the console goes ahead of agents and schedulers.
  • GET /status reports, per backend, the queue and the wait it can promise.

The router's configuration lives in the deployment manifest.
