Clusters

Clusters

DEVEX › Clusters (?tab=namespaces) is one page of sections: per cluster its health, namespaces and workloads, nodes and servers, serving tiers, training runs, instances, routing, PKI and GitOps. Older links (?tab=appConsoles, metrics, instances, routing, secrets, gitops, placement) open the matching section. Every read needs a console session.

Note: How to read absence. A source the console could not read is shown as unread, with the reason. An empty list means "none"; an unreadable one says it was not read. See Status and provenance.

Section What it shows
Health one headline for the cluster
Apps and agent planes the door grid: one card per tool you may reach, what it is for, whether it is up, how to open it. See Application consoles
Capacity node capacity and requests, drawn once
Namespaces problems first: admission posture, workloads with ready/desired, their pods, events, quotas, one verdict. Container logs are not read.
Self-heal and incidents what the ops doctor diagnosed and proposed, and the Disk steward (dry run; host-disk actions need Approve)
Serving tiers which model serves each tier, and where
Training runs the model training runs; shown only when a training server is attached
Instances the tenant ClientInstances: app, tenant, role, phase, readiness, endpoint
Routing how traffic reaches each service through the edge, and whether it is serving
Secrets & PKI the shared mesh CA as distributed to each namespace: fingerprint and expiry
GitOps desired versus running per workload, and drift. See GitOps
Cluster nodes, Servers outside the cluster, Managed hosts each machine once; an admin can Add a new server or Remove one, and open the node inspector
Details: scheduling and the console process collapsed by default

Reload re-reads the page.

Nodes & servers

One section for every machine; node capacity is drawn once. Servers are attached dynamically. The off-cluster section lists:

  • the off-cluster servers registered with the console, such as the inference server that serves the general and coder tiers, with the model tiers each one serves. A server that does not answer is shown unreachable with the reason;
  • any cluster node that serves a model, with what it serves.

Readings are cached for 20 seconds, so several viewers cost one read of the server. An admin can register a server from the last card.

GitOps

Delivery is a CI workflow: it builds the images a merge changed, applies the kustomize overlays, rolls the workloads, and records each deploy in the console's lineage record. There is no Argo CD. Per workload:

  • desired: the newest lineage record of the delivery workflow that planned or rolled the workload: commit, image, digest, run, time and roll verdict;
  • running: what the workload's pods report (image digests) and the version labels on the live object (app.kubernetes.io/version, runink.org/commit);
  • drift: decided on the digest when the build reported one, else on the commit label. It is null when neither pair could be read, never false.

The newest delivery runs are listed beside it. GitOps and Deploy lineage read one record; each links to the other.

Warning: A roll pins every container to an image digest. A bare restart of the workload restarts onto the same digest. To move a workload onto new images, run the delivery workflow for that image.
