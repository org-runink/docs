Reviews

Reviews

DEVEX › Agent runs › Reviews (?tab=reviews; its own DevEx row until 2026-10-31) shows the findings per review type. Every pull request in the org is reviewed on the platform's own model, and no review finding is left as a bare comment.

How a review runs

  1. Review. A pull request is reviewed when it opens or changes, or when someone asks with a tag such as @tidde_review. If findings remain, the pull request gets the label review:findings-open; only a clean review clears it. A review that could not run fails its check and says why on the pull request.
  2. Fix. The fixer opens a draft correction pull request onto the reviewed branch. It never merges. You can also ask for it with an @tidde_fix comment.
  3. Resolve. When the fixer cannot fix a finding, the resolver works on the branch in a coding session and opens a further draft. If it cannot resolve it, the finding stays open for a person.

Merging a draft onto the pull request branch re-triggers the review, and a clean review clears the label. "Resolved" therefore means the reviewer agrees, not that an agent said so.

A repository does not need its own review workflow: open pull requests across the organisation are covered centrally. The CI counterpart for FORGE and forged repos is central verification, which reports core/ci. See Central verification.

Comment tags

The tag-help agent answers any comment that looks aimed at TIDDE but carries no recognised tag, by listing the tags that work:

Tag What it starts
@tidde_review (also @tidde_check, @code_review, @review) sovereign code review of this PR
@tidde_fix a draft correction PR for this PR's findings
@tidde_deploy the deployer agent on a task issue
@tidde_ship [images] build image(s) and roll what runs them (default tidde-operator)
tidde @build a quick build and vet check
tidde @curate the curator
@tidde_datagov assess the connected data sources
@tidde_judgement judge the findings submitted to TIDDE

@tidde_review and @tidde_fix only work on a pull request; on an issue there is no diff to read.

Warning: @tidde_ship and @tidde_deploy are different commands: @tidde_deploy belongs to the deployer.

Where you see it in the console

DevEx › Reviews (?tab=reviews, GET /api/reviews) shows, per review type, what is running, the history, and the findings.

Type Runs from Findings from
code reviewer, fixer, resolver open PRs labelled review:findings-open
risk risk the "🛡️ Dependency risk report" issue
compliance compliance the compliance findings and the "📋 Compliance status" issue
dataQuality datagov runs the data governance findings
aiMaturity, dataMaturity none, computed on read the maturity assessment

A run whose findings were not recorded says so, never a zero count that would read as a clean review. A run's detail adds what the agents posted on GitHub.
