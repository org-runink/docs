Intelligence

Intelligence

Intelligence is what TIDDE knows about the data estate it manages. Since 2026-11-20 it is one rail row, Intelligence overview (?tab=resolve). Every figure comes from TIDDE's own services: a figure TIDDE cannot compute is drawn as absent, with the reason, never as zero.

A data-audit status bar sits above the tabs, with Open the data audit.

Tab What it holds Page
Overview functional lineage, OpEx, BI modelling proposals (Kimball or Data Vault), CRISP-DM and DAMA coverage Intelligence overview
Experiments & models experiment runs, registered models and their stages Intelligence overview
Discovery run discovery over the estate Intelligence overview
Estate & reconciliation sources, the estate map, reconciliation; Test, Explore and Map a source Estate
Graph the knowledge graph: search, neighbours, details, ingest Knowledge graph

If Intelligence is not set up yet, the overview names the first missing step and links to where it is done. The first step is a connection, made under Integrations.

Three rules every page follows

  • Absent is a state, not a zero. A figure that cannot be computed is a Kpi with no value and a non-empty absent_reason. Each response also carries a Provenance: LIVE, DEFAULT, EMPTY (nothing has been uploaded) or UNAVAILABLE (the store could not be read).
  • Reads never dial. A page load, a timer or a read RPC never contacts a tenant source. Only an admin's confirmed Estate action dials.
  • Writes are attributable and audited. Every non-read attempt is recorded in the console's audit chain, including refusals. With no sign-in configured, every write is refused.
