Overview page

The Overview page

Overview is the first page of the TIDDE console and the first row of its rail. It answers one question: is anything wrong, and where do I go next? It is a summary: each line links to the page that owns the subject.

What the Overview page shows

From top to bottom. A section with nothing to show draws nothing; what could not be read is listed on the page's Needs setup line, which only admins see.

Section What it is
What should TIDDE do? The goal box: type a goal and TIDDE plans it on AGENTS › Command.
Bird's-eye Every instance and application control plane you may see, at once. This is where you choose an instance: there is no instance switcher.
Start here A checklist for a new installation: Connect a data source, Test the connection, Map the estate, Run the first data audit, Invite a member. Each step links to where it is done. It disappears once dismissed or done.
KPI strip Client instances, workloads, agent runs and their success rate.
Needs attention The open findings of DataEx › Harness, worst first, and anything TIDDE could not do (for example an entitlements file it could not write).
Audit verdicts The Platform, Model & agent, and Data audit verdicts. Details opens the full audit: checks, actions and history.
Recent agent runs The newest runs from DEVEX › Agent runs.
Platform One line each for workloads, instances and inference, each linking to its page.

The page refreshes itself while it is on screen, and reloads at once when you come back to it.

An instance subscriber (someone who uses an instance but does not run the platform) sees a shorter console: their own home with the bird's-eye of their instances, and Admin when they administer one.

Ask TIDDE

Ask TIDDE is the assistant in the corner of every page. Ask it about what the console shows. Each answer can show its reasoning steps and the model that answered.

Ask TIDDE runs read tools at once. A tool that changes something, such as creating a client instance, is proposed, not run: you get the action and a one-time code, and nothing happens until you confirm it. On FORGE › Studio the same assistant speaks FORGE's commands.

What you type and what the model answers pass through the console's guardrail. The speaker and microphone buttons appear only when the installation has voice configured.
