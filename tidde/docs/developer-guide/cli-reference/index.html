CLI reference

CLI reference

The tidde binary is the single control surface for the platform. Everything on this page was taken from its --help output. Run tidde <command> --help for the authoritative text on your build.

Configuration

Resolution order (root.go, initViper): ./tidde.yaml, then ~/.tidde.yaml, then TIDDE_* environment variables (a . in a key becomes _), then flags. A missing config file is fine.

Global flags

Flag Default Meaning
--mode local local (multipass k0s, dev) or onhost (single-node k0s on this host)
--face-repo ../face path to the sibling FACE repo
--pulse-repo ../pulse path to the sibling PULSE repo
--control-ctx face-control shared control-plane VM and kube context (local mode)
--kustomize ./bin/kustomize path to the kustomize binary
--github-repo none owner/name for instance-request issues (or TIDDE_GITHUB_REPO)
--github-label instance-request issue label that marks an instance request
--console-url none, on purpose Runink TIDDE console base URL for session-run reporting (or TIDDE_CONSOLE_URL / console_url)
--image-pull-policy none override every imagePullPolicy the deploy applies: Always, IfNotPresent or Never (or TIDDE_IMAGE_PULL_POLICY)
--with-monitoring false also apply the shared inference monitoring stack (needs the Prometheus Operator)

--console-url has no default because TIDDE is deployed per client, each with its own console. Empty means "don't report": runs still record locally and tidde session sync delivers them later.

Command tree

Local development

Command What it does
`tidde dev up [face\ pulse\ all]` Start the dev stack (default: all)
`tidde dev secure [face\ pulse\ all]` Start the dev stack plus the single mTLS SNI gateway (unprivileged port)
tidde dev down Stop everything (backends, frontends, inference, gateway, mesh pipes)
tidde dev hosts [--remove] Map *.runink.org.local → 127.0.0.1 and grant the gateway :443 (one-time sudo)
`tidde dev flutter <face\ pulse\ core>` Hot-reload one Flutter UI against a backend. `--device chrome\ web-server,--endpoint,--port` (defaults 5551 face / 5552 pulse / 5553 core)
tidde dev frontend Launch only the local Flutter UIs pointed at real deployed instances. --face-url, --pulse-url (or TIDDE_REMOTE_FACE_URL / TIDDE_REMOTE_PULSE_URL)
`tidde app build\ flutter\ generate\ proto\ test ` Per-app dev tasks: build the Go backend, build and stage the Flutter web bundle, proto + build + test, regenerate protobuf (buf), run backend tests + flutter analyze

Cluster and deploy

Command What it does
`tidde cluster up\ status\ shell NAME\ models\ import VM IMG...\ down\ rm` Local multipass k0s lifecycle (alias clusters). models bind-mounts host GGUF dirs into the VMs; import loads images into a VM's k0s
tidde deploy platform Provision + mesh CA + CRDs + the TIDDE operator (no app instances)
tidde deploy face / tidde deploy pulse Deploy one app instance
tidde deploy all Platform + FACE + PULSE
tidde deploy down Tear down the overlays (local: stop VMs)
tidde build ambassador Build the shared static mTLS-proxy image
`tidde build operator <runink\ pulse\ core>` Build an operator image (+ the shared ambassador)
`tidde build app <face\ pulse>` Build an app's images from its sibling repo
tidde build inference-activator Build the scale-to-zero inference front-door image
tidde bump-fleet-image <app> <sha> Bump the image reference in a k0s-fleet overlay
tidde mesh ca [--namespace NS] Mint the shared mesh CA; with --namespace, distribute it to that namespace as a Secret
`tidde node dedicate --node N --app face\ pulse [--tenant T]` Dedicate a node to one app (label + taint)
tidde gitops render Render every GitOps kustomization offline
`tidde local up\ down` Install or remove the local suite (Calico, KEDA, Knative) on a fresh cluster with no CNI. Never on a cluster that already has one. (Its --help text still names Argo, which was removed.)
tidde status Show the reconciling desired state (platform + both app instances)
tidde smoke Security-surface smoke test (mesh CA + rotating-mTLS ambassador)
tidde dns sync Point endpoint hostnames at the edge IP via Namecheap (get → merge → set). --domain, --host (repeatable), --ip, --ttl (min 60), --dry-run

Warning: tidde build app builds local podman images (localhost/…). The images the cluster runs are built in the cluster. See CI Workflows.

Base images

tidde images list|mirror|preflight handles the sovereign base-image mirror. The declared set is the base-image manifest.

Flag (all subcommands) Default Meaning
--file the base-image manifest the declared base-image set
--ipv4 true force IPv4 for upstream pulls
--json false machine-readable output
--only none restrict to these images (repeatable)
--registry the set's own destination registry override
--timeout 30m0s per-request timeout

mirror adds --dry-run and --force. preflight reports which declared images are absent from the registry at the pinned digest and exits non-zero.

Instances and access

Command What it does
tidde instance request Open a GitHub issue requesting a new instance. Flags: --app, --tenant, --namespace (default tidde-system), --role, --image, --replicas, --compute-units (the resource size), --tag k=v, --user email[:role] (role `admin\ writer\ reader`)
tidde instance list [--issues] List reconciled ClientInstances, or open requests with --issues
tidde instance status Show reconciled ClientInstances on the cluster
tidde instance reconcile Provision instance-request issues and apply user-request grants, then report back
tidde instance add-user Open an issue granting users access to an existing instance: --instance or --app/--tenant, --namespace, --user email[:role] (default role reader)

Data connections

tidde connection register <manifest> registers data-source connections into TIDDE's console registry from a committed manifest. Flags: --dry-run, --adopt-drift, --rotate-credentials. It authenticates with a console session from the environment only. Full guide: Connections.

Security and compliance

Command What it does
tidde scan [repo...] govulncheck across repos. --fix applies reachable-CVE bumps (go get @fixed → tidy → build-verify), --json, --repo (repeatable), --timeout (default 10m)
tidde scan-sweep scan --fix across platform repos. --owner, --repos, --branch (default security/auto-update). No workflow calls it today
tidde security scan govulncheck + gosec per Go module per root, emitting SARIF. --roots, --sarif-dir
tidde security gate Ratchet the gosec SARIF against the committed baseline; fail on new findings or new coverage holes. --baseline-dir, --gate-severity (default MEDIUM), --stale-days (default 90), --update
tidde security report Aggregate SARIF into a report with the NIST SSDF mapping
tidde security autoupdate Auto-update vulnerable dependencies
tidde compliance gate Deterministic control checks over a repo; non-zero exit on findings. --repo, --changed-files, `--format text\ md\ json,--summary`
tidde compliance inventory Recompute the audit-emitter inventory (--write updates the policy)

Coding agent

Command What it does
`tidde auth login\ logout\ status` GitHub Device Flow sign-in. login takes --force and --no-browser
tidde session start Start a new coding session
tidde session resume <id> Resume a persisted session with a new instruction
tidde session list List persisted sessions
tidde session serve Run queued session instructions from the TIDDE console on this machine
tidde session sync Re-send pending session reports to the console

The session flags are covered in Coding sessions.

Install medium and wizard

Command What it does
`tidde guide-bundle build\ sign BUNDLE\ verify BUNDLE [SIG]\ keygen\ source` Build and sign TIDDE's install guide as a private guide bundle
tidde wizard Install Runink applications on a River node and create their admin logins. --serve runs the graphical wizard on a loopback-only page opened with a one-time link; --answers runs scripted
`tidde wizard status\ skip` Show what was installed; remove the first-boot login hint

Selected tidde wizard flags: --apps (from face,pulse,luna,forge; TIDDE is implied), --role server|runner, --offline, --online, --payloads, --passphrase-file, --state (default /etc/runink/wizard-state.json), --dry-run (runs against an in-memory fake node), --listen (loopback only; non-loopback is refused), --firstboot, --installation-admin, --admin (default on), --admin-user, --luna-owner-email.

Platform operations

Each line is the command's own --help summary. Run tidde <command> --help for its subcommands and flags.

Command What it does
tidde payload Build the private stick's payloads: per-app images, app bundles, and the no-reuse guard
tidde models The Runink Server's model set: check the lock, pin gated rows, convert a UQFF once
tidde mqtt The Runink Server MQTT broker: device certificates
tidde evidence Check release-evidence documents (runink.release-evidence/1): validate, lint, public-view
tidde review-trigger Kick the TIDDE review sweep unless one is already waiting
tidde registry-keeper Keep the node-local registry and the node's disk inside their budget
tidde zfs-janitor The disk steward: observe the node's ZFS pool, reason, and reclaim on a gated allowlist
tidde snapshot Work with the committed sibling snapshots
tidde lint Repository lints (shell-ratchet: no new shell; the list only shrinks)
tidde rename The one cut-over to the TIDDE object names: copy, stop, swap, apply, verify, retire (dry-run unless --apply)
tidde migrate-namespace Move FACE from its legacy namespace to face-system, one step at a time (dry-run unless --apply)
tidde bench Acceptance benchmarks against a running stack (p50/p95 per phase)
