API Reference

API Reference

This page is the reference for every API behind Intelligence:

  • the gRPC-web services (runink.ui.estate.v1 and runink.core.ask.v1);
  • the policy class of each RPC;
  • the Intelligence JSON routes.

Transport

The Intelligence services and Ask are served as gRPC-web inside the console process:

  • Same origin and session. They share the origin of the console and the session cookie of every /api/* call. There is no separate port.
  • No CORS. A request whose Origin names another site gets HTTP 403 cross-origin gRPC-web is not served by the console.
  • Session. With sign-in configured, a call without a valid session is UNAUTHENTICATED (unauthorized — the console session is not valid; sign in again).
  • Message cap. One message may be up to 16 MiB.
  • Reading failures are not errors. "We could not look" is a normal response with provenance.source = DATA_SOURCE_UNAVAILABLE and an unmeasured[] reason. Error statuses are reserved for bad requests (INVALID_ARGUMENT, NOT_FOUND, FAILED_PRECONDITION), refusals (UNAUTHENTICATED, PERMISSION_DENIED) and UNIMPLEMENTED.

Classes:

  • read: any admitted identity.
  • attributable: a session on a console with sign-in.
  • admin: the Intelligence-admin list.

A method missing from the table is admin-write.

The four dialing requests carry an optional runner field. See Estate.

AskService (runink.core.ask.v1)

RPC Class
Describe read
Ask (server stream) a session on a console with sign-in

Any other streaming method is refused: the console serves no streaming RPCs except AskService/Ask.

Intelligence HTTP routes

These routes return JSON. The GET reports answer 200 even when they could not read their source, and say so in the body as source:"unavailable" / complete:false, with an unmeasured[] list.

Route Method Auth What it is
/api/swarm GET session Agent swarm: fleet health, roster, run/latency rollup
/api/domains GET session Data domains clustered from the connection registry
/api/governance GET session Estate governance: ownership, credential storage, namespace posture
/api/data-lineage GET session Declared topology and observed flows
/api/data-lineage/edges POST bearer the ingest credential Apps' observed-lineage ingest
/api/compliance GET session Per-control findings. Never a score, never a framework mapping
/api/maturity GET session Five measured dimensions, plus a composite only when all five are measured
/api/governance-runs GET [?repo=] session Run history for the governance-family agents
/api/data-governance-findings GET / POST session (GET), App token via authorizeReporter (POST) datagov findings
/api/lineage GET [?sha=] session Deploy lineage per image
/api/playbook-runs/step-report POST App token (authorizeReporter) A dispatched agent reports its step of a goal plan
/api/playbook-runs/approval POST session A person decides a goal plan's approval step

Token-door errors:

Condition Response
Wrong token 403: bad ingest token
App-token door with no bearer 401: missing bearer token
