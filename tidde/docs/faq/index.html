FAQ

FAQ

Questions that cut across the sections. Each answer links to the page with the detail.

General

Is Runink TIDDE the same as Kubernetes? No. TIDDE runs on k0s and deploys with kustomize, without Helm. It adds its own operators, the ClientInstance tenant API, the security services, the agent fleet and the console. See Architecture.

Do the apps depend on TIDDE? No. FACE, PULSE and LUNA do not import TIDDE; each carries a test that fails if it does. Code more than one of them runs lives in shared libraries.

How do I get access, and how do I sign in? Sign-in is for approved accounts only. Creating an account on the sign-in page does not give access: your address must be on the approved list. Runink adds your organisation's admins, and an instance admin adds members. An approved address signs in with Google at your installation's console URL. See Sign in and Access and roles.

Which models does TIDDE use? Does it call a hosted AI service? It calls no hosted model. Every model is served on Runink's own inference servers or on your cluster. See Models and inference.

Does TIDDE send my data anywhere? TIDDE reads a data source only when an admin runs one of its actions on Intelligence overview (Test, Explore, Read access patterns, Map estate), or when a runner you connected runs an approved job. Reads of the console never dial a source. See Intelligence overview.

Where are prices and plans? On the Runink TIDDE product page, not in this guide. What an admin needs to know about the trial is on Trial and subscription.

Is TIDDE on Android? Not yet.

AGENTS

Can TIDDE act on its own? Plans and automatic actions run only inside an armed autonomy policy, with budgets, and with a stop button. Self-improvement is off until an agent admin turns it on (it has not run yet). See Autonomy and Goals, plans and autonomy.

Does TIDDE change its own code or models? Self-improvement is built, but it has not run yet. When it runs, every action is shown on AGENTS › Improvements, and an agent admin can request a revert. Developer goals end in a draft pull request; execution is off by default, and merging stays with a person. See Improvements.

Why does the judge report "unable to judge"? Its docket is filled only by an external assessment platform that an admin has given an ingest credential. Until then the docket is empty and the judge says so rather than guessing. Unable-to-judge is never shown as agreement. See Judge.

DEVEX

How long does a coding session take? Budget in decode time. On CPU-only hardware the coder tier decodes a few tokens per second, so a 40-turn session is roughly an hour. See Coding sessions.

Where did Argo CD go? It was removed. Delivery is a workflow in Runink's own CI, and DEVEX › Clusters compares what it delivered with what is running. See Clusters.

Why are reviews slow and one at a time? The engines decode a bounded number of requests at a time and the model router queues the rest. See Reviews.

DataEx and Intelligence

Does TIDDE scan my data every day? The data governance agent runs daily, but it reads no rows and no values. It assesses quality and personal-data exposure only from the structure and counts that Explore recorded. A source nobody explored is reported unassessable, with the reason. See Data governance.

What is the difference between findings and judgements? A finding is a claim made by an agent or an assessment platform. A judgement is TIDDE's own verdict on a finding an external platform submitted: concur, dissent, unable to judge, or out of scope.

FORGE

Is FORGE a separate site? No. FORGE is a section of the TIDDE console under TIDDE's sign-in. There is no FORGE domain and no FORGE login, and the old standalone FORGE documentation redirects here. See FORGE.

Can I run an app FORGE built? Not yet. FORGE builds and verifies a repository; running a forged app is not yet available.

Who runs CI for a forged repository? TIDDE does, centrally. Forged repositories carry no CI of their own and no App credentials. TIDDE posts the result as the core/ci commit status. See Central verification.
