      Navigation

      Navigation

      Every page after sign-in shares one frame: the navigation rail on the left, the session fetch strip across the top, and the assistant at the bottom right. The rail is the only menu. Pages have no second tab bar of their own.

      The rail

      The rail has four labelled sections, in the order of FACE’s loop. Every page a section owns is listed under its heading, so nothing is hidden behind a collapsed entry.

      SectionEntries
      RECONCILEReconcile · Entities
      FETCHFetch · Connections · Knowledge · Schedules
      SIMULATESwarm Intelligence · Rules · Metasearch Trends · Causal Matrix
      TWINSMap · Today’s command

      The footer holds Account (your profile) and Billing (billing and usage). Below them are the signed-in account, with sign-out beside it, and a chip naming the instance FACE is acting for. Select the chip to choose another instance.

      Admin is not a rail entry. It opens from your Account page, and only an admin of the selected instance sees it there.

      Pages that are not in the rail light the entry they belong to:

      You are onLit entry
      A past run, or a live view opened from a connection card (Surveillance, Devices, Field reader, Live sensors)Fetch
      The connect wizard, the camera check or the web scraperConnections
      A schedule formSchedules
      A scenario’s detail pageSwarm Intelligence
      A remediation screen, a decision artifact, a voice call or the support logToday’s command
      AdminAccount

      Older links keep working. Each old address forwards to where its content lives now. For example, the old twins address opens Today’s command, the old document extraction address opens Knowledge, the old orchestrator address opens Swarm Intelligence, and the old rules address opens Simulate › Rules.

      Each rail entry is a button with a visible focus ring. Screen readers announce its label and whether it is the page you are on.

      The session fetch

      Right after you choose an instance, the cockpit starts a session fetch in the background. It is the first reading of your data. When it completes, the pages that read it (Reconcile, the rules on Simulate, and the Twins map) read its results again by themselves. The session fetch runs once per session, whichever page you open first.

      The session fetch strip

      The strip across the top of every page, titled Session fetch, states how the last session fetch ended, with its reason. Open audit opens that run’s record on Fetch.

      The activity card

      While any fetch runs, a card in the centre of the screen narrates it. That covers the session fetch, a fetch you start yourself and a scheduled fetch. It also covers the other long operations: testing a connection, uploading or indexing documents, document extraction, an agent run and a web scrape.

      • The headline says what is running, for example Running the session fetch… or Running your fetch…, and then how it ended: Session fetch finished, Fetch failed, and so on.
      • The steps are the run’s phases as the server reports them: the runner query, SQL generation, profiling, business domains and business rules. Each step is marked running, done, failed, out of time or skipped. The card lists which phases worked and which did not, not only that the run finished.
      • Show reasoning opens the run’s full reasoning.

      The card keeps clear of the assistant button. If several operations run at once, the card shows the most recent one.

      The inference notice

      If the model plane is not ready, a strip under the session fetch strip says so:

      • AI is warming up… while the models load.
      • Inference is not ready — AI features are unavailable. when they cannot answer.

      The strip adds Everything that needs no model works now. and offers Check again. It disappears once inference is ready.

      The FACE AI assistant

      The round button with the Runink mark, at the bottom right of every page, opens the assistant. Its tooltip is FACE AI, and screen readers announce it as Open FACE AI assistant. The panel is the same assistant PULSE uses, and it floats over the page.

      The assistant knows which page you are on. On Fetch or Connections it suggests Create new connection and Find extra docs. On any other page it suggests Help me with this screen and What can I do here?.

      ControlLabel
      Text boxAsk FACE…
      SendSend message
      MicrophoneSpeak your question. It is submitted when you stop.
      CameraTake a photo
      AttachmentAttach a file

      The answer lists every step FACE ran as done, failed or blocked, with the reason underneath. How this was worked out shows the reasoning. FACE AI could not answer means the request failed, and the reason follows it. No answer came back means the assistant finished but returned nothing to show.

      If voice input is blocked, the panel says Voice input is unavailable in this browser or the microphone was blocked. Type your question instead.

      Behind the frame: FetchService.RunFetchStream, ModelService.GetModelStatus and ActivityService. See the API reference.
