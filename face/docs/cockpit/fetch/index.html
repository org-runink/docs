      Using the cockpit
      Fetch

      Fetch

      Fetch Center is where you ask your data a question, and where you choose which connections and runners FACE may use. Open it with Fetch, the first entry under FETCH in the rail (/fetch).

      The page has four entries, from top to bottom:

      1. The question box (Ask a question or use voice command…), where you type, dictate or attach a question or a command.
      2. FETCH STARTERS: prepared questions. They step aside once you have said what you want.
      3. ACTIVE CONNECTIONS: one card per connection, each with an Active switch.
      4. COMPUTE RUNNERS: one card per runner, each with an Active switch.

      Below them is the EXECUTION HISTORY, with each run and its phases.

      The status line

      The banner at the top says where you stand, and it offers the next step:

      You seeButton
      A fetch is running…
      Checking your configured sources…
      Could not load your data sources., with the transport errorRetry
      No data source is configured yet.Connect a data source
      Sources are configured, but no fetch has run on this device yet.Ask your first question
      Your last fetch failed.Open the run
      Your last fetch is queued offline and has not run yet.Open the run
      Your last answer came back low-confidence.Ask again
      Your last answer was reused from cache, not fetched live.Ask again
      Your last fetch succeeded.Ask a new question

      Could not load your data sources. means the cockpit could not look. No data source is configured yet. means it looked and found no sources.

      Start here

      Until your first fetch has run, a Start here panel sits above the starters: From no source to your first fetch. Each step is read from the platform, never ticked by hand. Its steps are Connect a data source, Have a runner ready and Run your first fetch. Each says whether it is done, and Could not check this step. when the platform could not be asked. The panel disappears once every step is done.

      Active connections and runners

      Fetch controls which connections and runners FACE may use.

      Connection cards

      Under ACTIVE CONNECTIONS, each configured connection has a card. Select the heading to open Connections. New connection, beside it, opens the connect wizard.

      Each card shows:

      • the connection’s name and type;
      • a caption: Included in fetch or Not included for an active connection, and Switched off: not read by Fetch for one that is switched off. The caption describes your selection. It does not say whether the source is reachable;
      • what the server holds for the source, such as whether its credential is stored. This is not a reachability check;
      • the Active switch;
      • for a live connection type, a button that opens its live view (see below).

      Tap an active card to include it in, or exclude it from, your next fetch. When the connection list loads live, every active connection starts out included. A switched-off connection cannot be included.

      The Active switch

      The Active switch on a connection or runner card turns it on or off for every fetch on the instance: yours, other people’s and scheduled ones. The server enforces it. A fetch that names a switched-off connection or runner is refused, with the reason.

      Only an admin of the instance can flip the switch. Everyone else sees the state as text: Active or Inactive. If a switch cannot be saved, {name} was not switched: {error} gives the reason, and the switch stays where it was.

      Switched-off connections also drop out of the Twins map’s live layers.

      Live connection types

      Some connection types are live feeds rather than stores. Their cards on Fetch open a live view, already narrowed to that one connection:

      Connection typeButtonOpens
      Video Stream (cameras)SurveillanceSurveillance
      MQTT Bus, Sensor Gateway, GPS Telematics, RFID ReaderLive sensorsLive sensors
      Runink Edge (a handheld field reader)Field readerField reader
      Any source that reports devicesDevicesDevices

      A narrowed view says Connection {id} only. Show all widens it to every connection of that type. Live sensors, in the link row above the history, opens the live sensors view for all connections.

      Runner cards

      Under COMPUTE RUNNERS, each runner registered for the instance has a card with its own Active switch. Tap an active runner to run your next fetch on it. The highlighted card, marked Active, is the runner the next fetch will actually use. Other active runners show Standby, and a switched-off one shows Switched off and cannot be picked.

      When you have not picked a runner, or your pick is switched off, the fetch runs on the managed runner if it is active, otherwise on the first active runner. New runner, beside the heading, opens the runners on Connections. No compute runners registered yet. means the list was read and is empty.

      Run a fetch

      Choose your sources

      Under ACTIVE CONNECTIONS, tap a card to include or exclude it (see Connection cards). Optionally, pick a runner under COMPUTE RUNNERS.

      Ask your question

      Type in Ask a question or use voice command…, or tap a card under FETCH STARTERS to fill the box with a prepared question. To add input, use the buttons beside the box:

      • Voice Input dictates. Dictation stops after a pause and the fetch starts by itself.
      • Camera Input attaches a photo.
      • Attach File attaches one or more files.

      Attachments appear as chips that you can remove.

      Choose how to be told

      Call Me When Finished and WhatsApp Me ask FACE to notify you when the run ends.

      Run it

      Press Enter or select Run Fetch. A progress dialog, Analyzing your data…, lists each step as the server streams it. A finished step gets a check mark. The dialog shows Ready and closes when the run ends.

      Read the answer

      Under Twin Insights, the spoken summary comes first, followed by the cards. The summary is also read aloud.

      A photo taken with Camera Input is also offered to the surveillance pipeline. The snackbar tells you which of three things happened: the photo was offered, the offer failed, or it was attached to the prompt only. The photo is listed under Captured media on Reconcile.

      If the cockpit cannot reach the server, the run is queued on your device (Offline mode: Fetch task queued for background synchronization.). It runs when the connection returns.

      Twin Insights

      CardShows
      DecisionThe recommendation, a {percent}% confidence badge, and Why:, Plan: and Risks: lines.
      Recommended ActionA priority badge and Impact:.
      ForecastForecast:, and an ANOMALY badge where one was detected.
      SignalIts source and Relevance:.

      Each proposed action is judged before it reaches you. A decision or action card that was judged carries a footer: Judgement: followed by concurs, dissents, unable to judge — not agreement or out of scope — not judged, then the judge’s reason. assessed by the model or checked without a model says how the verdict was reached. An action the judge dissented from is removed from the answer and listed under Actions rejected, with a count of how many actions it concurred with, dissented from, or could not judge.

      Execution history

      EXECUTION HISTORY lists your runs, newest first. The automatic session fetch and scheduled fetches are listed here too. While a run is in progress, the activity card shows its phases. Each run card shows the command, the result or error, the duration, Runner: and Connections:, and a provenance badge. The badge reads Live, Cached, Offline — queued, Low confidence or Failed.

      • Reuse Prompt runs the same command again.
      • Delete Execution removes that one run, after you confirm Delete this run?.
      • Clear Log clears the whole history, after you confirm Clear Execution History.

      Run history is stored on this device.

      Below the runs are traces: the lineage datasets FACE has recorded, with the schema and how fresh each one is. Tap a trace to open its details: rows, size, freshness, columns, downstream datasets and the description.

      Open a past run

      Tap a run card to open Fetch details (/fetch/run/<id>). It shows:

      • the status: Completed, Failed or Queued offline;
      • Query, Runner, Connections, Started and Duration;
      • Error, when there was one;
      • Result;
      • What happened to the sources: notices about individual sources, word for word;
      • AI analysis;
      • Generated SQL.

      Reuse Prompt in the title bar returns to Fetch Center and runs the command again. This run is no longer in your history. means the run was deleted or the history was cleared.

      Schedules

      Open Schedules under FETCH in the rail, or Fetch Schedules in the link row above the history. The page is Active Schedules (/active_schedules). The subtitle counts the tasks, for example 2 OF 3 TASKS RUNNING.

      • The filter menu (Filter Tasks) offers All, Active only and Paused only.
      • Each card shows ACTIVE or PAUSED, FREQUENCY, NEXT RUN and LAST RUN.
      • The switch (Toggle schedule status) pauses or resumes the schedule.
      • Edit Schedule opens the schedule form.
      • Delete Schedule asks Delete schedule? before it deletes.
      • CREATE NEW SCHEDULE opens a blank form.

      No schedules match this filter. means the list loaded and nothing matched. A failed load shows the error instead.

      Create a schedule

      Open the form

      Select CREATE NEW SCHEDULE. The form is titled SCHEDULE FETCH — Automate Data Discovery.

      Pick the task

      Under TASK CONFIGURATION, choose a FETCH TOPIC from the fetch starters and a RUNNER TYPE.

      Pick the frequency

      Under RECURRENCE LOGIC, choose DAILY, WEEKLY or MONTHLY. NEXT RUN shows when it would next run.

      Save

      Select SAVE SCHEDULE. Schedule Saved Successfully closes the form. Could not save the schedule. It was not created. means nothing was stored.

      Scheduled runs send no alerts. The form says so under NOTIFICATIONS. To be told when a run ends, turn on Call Me When Finished or WhatsApp Me for a run you start yourself.

      Decision artifacts

      A decision artifact is the full record of one proposed action, with the drafts it would produce: an email, a calendar invite, an ERP change. Open one from a Today’s command order or a card on the Twins map:

      • View full decision artifact opens a preview, marked PENDING. Approve All approves the action.
      • Approving a card that has artifacts opens the outcome, marked QUEUED. The footer reads Action approved — queued for execution.

      The page shows DECISION ARTIFACT #{id}, the title, the decision trail and the GENERATED DRAFTS. A link that carries no decision shows No decision artifact.

      Other pages linked from Fetch

      • ACTIVE CONNECTIONS (the heading) opens Connections.
      • New connection opens the connect-a-data-source wizard. Document sources, cameras and web pages are source types in that wizard.
      • Swarm Intelligence, in the link row above the history, opens Simulate › Swarm Intelligence, where the agent orchestrator now lives.
      • Live sensors opens the live sensors view.

      • FetchService.RunFetchStream (server stream), ListFetchStarters, ListTraces, GetTraceDetails.
      • ConfigService.ListConnections, ListRunners, SetConnectionActive, SetRunnerActive (admin only).
      • SchedulesService.ListSchedules, CreateSchedule, UpdateSchedule, SetScheduleActive, DeleteSchedule.
      • ModelService.SpeakFetchSummary, SynthesizeSpeech.
      • TwinsService.ExecuteAction, for Approve All.
