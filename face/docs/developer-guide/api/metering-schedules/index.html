Schedules

Schedules (and the deprecated metering service)

SchedulesService keeps the recurring fetches that the FACE app shows as Briefs (Fetch section). In the protos a brief is a Schedule. MeteringService is deprecated: FACE does not charge by usage, and every figure it returns is 0.

Summary

Service RPC Kind Purpose
SchedulesService ListSchedules Unary List schedules
SchedulesService CreateSchedule Unary Create an active schedule
SchedulesService UpdateSchedule Unary Replace a schedule's title, description and frequency
SchedulesService SetScheduleActive Unary Pause or resume a schedule
SchedulesService DeleteSchedule Unary Delete a schedule

MeteringService (deprecated)

Full name semantics.v1.MeteringService. Kept only so existing clients keep working; do not build on it. GetResourceUsage returns 0 for every figure, with the reason in unmeasured_reason: show that reason, never a 0 as a cost. GetComputeBudget and SetComputeBudget read and set a legacy figure that gates nothing: a fetch is never refused because of it, and SetComputeBudget refuses a reader.

SchedulesService

Full name semantics.v1.SchedulesService.

A schedule triggers a fetch at a fixed interval. Its title is sent as the fetch command, and it runs on the managed runner under a short-lived service-account session. Schedules are stored durably and fire on the control plane only.

Note: Firing a schedule runs a real fetch only when the operator has enabled scheduled execution on the deployment. Otherwise each due run is recorded as <time> — skipped (execution disabled), with last_run_success: false, and run_count does not increase.

Frequency. frequency is free text. The server reads the interval from it, case-insensitively:

Text contains Interval
6 hour 6 hours
hour 1 hour
dail or day 1 day
week 1 week
month 30 days
custom 1 day
anything else, or empty 1 hour

The stored label is the text you sent, with its first letter capitalised and the rest lowercase. On create, an empty frequency is labelled Daily but, per the table, fires hourly. Send an explicit frequency.

If a run is still in progress when the schedule is next due, that interval is skipped.

Event triggers. A schedule whose trigger is event has no interval: it runs when the connection's data listener has seen min_events matching events, debounce_seconds after the first of them, at most once per cooldown_seconds, and never while its previous run is in progress. The run is a fetch with trigger_type: TRIGGER_TYPE_EVENT and job_id event:<schedule id>:<first>-<last position>; the schedule's event_state records the events that fired it and the run's transaction id. The fetch carries those events (trigger_events, with trigger_connection_id); the runner reads the rows they name back and the run's analysis reports, per rule, which of them conform or break it (last_fire_rules). Only the control plane's event trigger can set trigger_events: a client-set value is cleared on receipt. Creating or resuming an event schedule turns the connection's listener on; pausing or deleting the last active one on that connection turns it off.

ListSchedules

rpc ListSchedules(ListSchedulesRequest) returns (ListSchedulesResponse);
  • Kind: Unary.
  • Auth: Bearer session.
  • Errors: None beyond authentication.

Returns every schedule. The first time a new instance starts, it may already hold example schedules.

Request: ListSchedulesRequest

No fields.

Response: ListSchedulesResponse

Field Type Description
schedules repeated Schedule All schedules.
listeners repeated DataListenerMetering Every connection whose data listener is on, with the state the runner last reported and the usage metered. Listing never dials the runner.

CreateSchedule

rpc CreateSchedule(CreateScheduleRequest) returns (Schedule);
  • Kind: Unary.
  • Auth: Bearer session, writer, admin or service account.
  • Errors: INVALID_ARGUMENT if title is empty or the trigger is invalid (an unknown kind, no connection, a debounce outside 0–3600 s, a cooldown outside 60–86400 s, an operation other than INSERT, UPDATE, DELETE or PRODUCE). NOT_FOUND if the trigger names no connection on this instance.

Creates an active schedule whose first run is one interval from now. The id is a slug of the title, with -2, -3 and so on added when the slug is taken.

Request: CreateScheduleRequest

Field Type Description
title string Required. Also the fetch command the schedule runs.
description string Free-text description.
frequency string Interval text. See Frequency. Ignored for an event trigger.
trigger ScheduleTrigger Optional. Absent or time makes a time schedule.
notify ScheduleNotify Who the runs tell, and when. Unset means the schedule tells nobody.
first_run_unix int64 When the first run fires, for a time schedule. It must fall after now and within one interval of it. 0 means one interval from now. Refused on an event trigger.
persona_id string The persona the brief is for. Empty means nobody in particular.
connection_ids repeated string The connections the brief reads. Each must be a connection on this instance (INVALID_ARGUMENT names one that is not). Empty means every connection, at each run.

Response

The created Schedule.

UpdateSchedule

rpc UpdateSchedule(UpdateScheduleRequest) returns (Schedule);
  • Kind: Unary.
  • Auth: Bearer session, writer, admin or service account.
  • Errors: INVALID_ARGUMENT if title is empty. NOT_FOUND if no schedule has id.

Replaces the title and description with the values sent, so an empty description clears it. An empty frequency keeps the current one. If the frequency changes and the schedule is active, the next run is one new interval from now. The run history and the active flag cannot be changed here.

Request: UpdateScheduleRequest

Field Type Description
id string The schedule to edit.
title string Required. New title.
description string New description. Replaces the old one.
frequency string New interval text. Empty keeps the current frequency.
trigger ScheduleTrigger Optional. Changing the trigger discards events counted under the old one.
notify ScheduleNotify Replaced like the other fields. Unset means the schedule tells nobody.
persona_id string Replaced. Empty means nobody in particular.
connection_ids repeated string Replaced. Empty means every connection, at each run.

Response

The updated Schedule.

SetScheduleActive

rpc SetScheduleActive(SetScheduleActiveRequest) returns (Schedule);
  • Kind: Unary.
  • Auth: Bearer session, writer, admin or service account.
  • Errors: NOT_FOUND if no schedule has id.

Resuming schedules the next run one interval from now. Pausing clears the next run (next_run_unix: 0, next_run: "Manual Resume Req.").

Request: SetScheduleActiveRequest

Field Type Description
id string The schedule.
active bool true to resume, false to pause.

Response

The updated Schedule.

DeleteSchedule

rpc DeleteSchedule(DeleteScheduleRequest) returns (DeleteScheduleResponse);
  • Kind: Unary.
  • Auth: Bearer session, writer, admin or service account.
  • Errors: None. An unknown id returns success: false.

Request: DeleteScheduleRequest

Field Type Description
id string The schedule to delete.

Response: DeleteScheduleResponse

Field Type Description
success bool true if a schedule was deleted.
