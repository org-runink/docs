Fetch & traces

Fetch & traces

A fetch is FACE's main pipeline. It reads the selected data sources on a runner, profiles and reconciles them, runs the posture, rules, hypothesis and twin agents on the sovereign model plane, and returns one analysis with decisions, action cards and their judgements. FetchService starts fetches, streams their progress, lists past runs, and generates procedures.

Fetches always execute on a runner, never on the control plane. The control plane hands the work to an enrolled runner or dials the managed runner (see Configuration, connections & runners). A fetch has no usage charge and no limit of its own.

Summary

Service RPC Kind Purpose
FetchService RunFetch Unary Run a fetch and return the analysis
FetchService RunFetchStream Server streaming Run a fetch, streaming phase progress
FetchService ListTraces Unary List saved sessions (order and claim workflows)
FetchService GetTraceDetails Unary One run's command, analysis and SQL
FetchService GenerateSOP Unary Draft a standard operating procedure
FetchService ListFetchStarters Unary Suggested fetch prompts
FetchService ListFetchRuns Unary The fetch run history
FetchService GetFetchAttachments Unary What one run read off its attachments
FetchService GetRunStoryboard Unary One run's question, strict verdict and storyboard
FetchService GetAskLayout Unary One run's Ask answer, block by block, as the run stored it
FetchService GetScenarioGraph Unary One run's scenarios as a mind map, shared leaves drawn once

FetchService/GetDispatchKey is internal to the platform (served only by a runner, and only to a verified mesh peer) and is not documented here.

FetchService

Full name semantics.v1.FetchService.

RunFetch

rpc RunFetch(RunFetchRequest) returns (RunFetchResponse);
  • Kind: Unary. A fetch can take many minutes: set a generous deadline, or use RunFetchStream.
  • Auth: Bearer session, writer, admin or service account. A reader cannot run a fetch.
  • Errors: None beyond authentication. Every outcome is in the response. Check success and message:
Situation Response
No runner available or reachable success: false, message says so. The fetch never runs on the control plane.
No selected source could be read success: false, message names each source and why.
Some analysis phases failed success: false, message gives the verdict, and analysis carries what was produced.
Complete success: true, transaction_id and analysis set.

Read analysis.source_notices even on success: it reports sources that could not be read and where SQL actually ran.

Request: RunFetchRequest

Shared by RunFetch and RunFetchStream.

Field Type Description
command string What to analyse, in plain language, for example Which shipments are running late, and why?.
documents repeated string Attachments, each a data: URI with the file's contents (data:<type>;name=<file name>;base64,<bytes>). The fetch reads each by what its bytes are, not by the declared type: photos (JPEG, PNG, TIFF, WebP), PDF (text layer and scanned pages), DOCX, PPTX, XLSX and plain text. Others are skipped with the reason. What it read is in analysis.attachments and GetFetchAttachments. A spreadsheet uploaded with AskAttachmentService is sent as attached:<attachment_id> instead, and read as an Excel connection reads a workbook: every sheet a table.
connection_id string The primary data source.
runner_id string The runner to use.
enrichment_connection_ids repeated string Additional sources to read.
trigger_type RunFetchRequest.TriggerType What started the run.
schedule_config string Optional cron expression or description.
job_id string Your job id. Used as the charge reference when there is no transaction id.
language_preference string Preferred language for the analysis.
notify_via_call bool Phone the carrier number in the integration config once every phase of the run has ended, not when the answer returns. The message says how the run ended: finished, partly finished (naming each phase that did not finish, and why), interrupted by a server restart, or failed. A finished run's message adds the spoken summary. Sent once. Nothing is sent if no number is configured, or if the server stops before the run's phases end.
notify_via_whatsapp bool The same message as notify_via_call, at the same moment, to the WhatsApp number in the integration config. Nothing is sent if no number is configured.
session_eda bool Run only the fast first phase (data domains, maturity, rules reconciliation, knowledge graph) and skip the deep hypothesis and twin agents.
synapse_threshold double Minimum absolute Pearson r for the pass to record a measured link ("synapse") between two data domains. 0 means the default, 0.5. Higher values give fewer, stronger links.
dispatched_connections repeated Connection Internal. Set by the platform when it forwards work to a runner. A client value is overwritten or ignored.
dispatch_id string Internal. As above.
dispatched_credentials repeated SealedCredential Internal. As above. Clients never see or send credentials here.
trigger_events repeated DataEvent Internal. Set by an event-triggered schedule: the change events that fired the run. A client value is cleared.
trigger_connection_id string Internal. As above: the connection whose data listener saw them.
persona_id string Who the run is for: a product persona's id (ops, cfo, cro, cmo, ceo), a persona this instance saved, or empty for the generalist view. It changes what the answer leads with, never what data it reads. An id that names no persona is refused with INVALID_ARGUMENT.
dispatched_persona, dispatched_external_search Persona, ExternalSearchPolicy Internal. The control plane overwrites both when it forwards work to a runner. A client cannot set them.
public_sources PublicSourceChoice (repeated string source_ids) The public sources this run reads, by the ids ConfigService/ListPublicSources returns. Unset means the server's default. Set means exactly those ids, and none when the list is empty. An id the server does not know is named on the run and read as nothing. It can only narrow what a run reads: the tenant's external-search policy still decides what may leave.

Response: RunFetchResponse

Field Type Description
success bool true only for a complete run.
message string Why, when success is false.
transaction_id string The run's id, also used as the trace id.
analysis FetchAnalysisResult The analysis. Also present on a partial run.

RunFetchStream

rpc RunFetchStream(RunFetchRequest) returns (stream RunFetchUpdate);
  • Kind: Server streaming. Available over native gRPC and gRPC-web.
  • Auth: Bearer session, writer, admin or service account. A reader cannot run a fetch.
  • Errors: Outcomes arrive in the stream, as for RunFetch. The stream can end with an error only if forwarding to the runner fails in transport.

Runs the same pipeline and streams real progress as each phase completes: data_health, rules, scenarios, recommendations, and a terminal final event that carries the full RunFetchResponse in result. A refused request is a single denied event with done: true. A recent identical request may be answered from an earlier run, and the result's provenance then says so.

The final event's message is "Answer ready": the answer is back, and the phases after it (the analysis, which judges the scenarios, and the twins decisions) still run. It does not say the run succeeded. Read the run's verdict (ListFetchRuns, GetRunStoryboard) for that.

Response: RunFetchUpdate

Field Type Description
phase string data_health, rules, scenarios, recommendations, final, or denied.
message string Human-readable progress, for example Data health checked.
done bool This phase, or for final and denied the whole run, is complete.
result RunFetchResponse Set only on the final event.

ListFetchRuns

rpc ListFetchRuns(ListFetchRunsRequest) returns (ListFetchRunsResponse);
  • Kind: Unary.
  • Auth: Bearer session. The caller's own runs; an org admin gets every run in the tenant.
  • Errors: UNAUTHENTICATED with no signed-in caller. FAILED_PRECONDITION on a runner, or on a process that records no run history. UNAVAILABLE if the history cannot be read.

The fetch run history, newest first. The control plane records one run for every RunFetch and RunFetchStream call it receives from a signed-in caller, including fetches it refuses. A run carries no result. Its verdict carries the question it was asked and which of its phases finished (see RunVerdict).

A run is recorded twice: as FETCH_RUN_OUTCOME_RUNNING when the control plane receives it, and with its outcome when it answers. Both records share run_id, and the response lists the run once, with the later outcome. If the control plane stops before the run answers, no outcome is ever recorded. Such a run is listed as FETCH_RUN_OUTCOME_INTERRUPTED once it is older than the 300-second fetch limit plus a 60-second margin, with ended_unix_ms 0 and a message saying the server stopped before it finished. Before that it is listed as running. With object storage configured, runs are kept for 30 days; without it, the newest 500 records (a run's start and end are two) are kept in memory and lost on a restart.

A run is successful only when every phase finished, including the phases that run after the answer. outcome says only whether the response came back; read verdict for whether the run succeeded.

Request: ListFetchRunsRequest

Field Type Description
limit int32 Maximum runs. 0 or negative means 20. Capped at 200.
include_archived bool Also list archived runs, each marked archived, so they can be restored. Org admin only: anyone else is refused.

Response: ListFetchRunsResponse

Field Type Description
runs repeated FetchRunSummary Newest first.
durable bool False when the history is kept in memory only.
not_durable_reason string Why, when durable is false.

GetScenarioGraph

rpc GetScenarioGraph(GetScenarioGraphRequest) returns (ScenarioGraph);
  • Kind: Unary.
  • Auth: Bearer session. Only a run in the caller's own run history (an org admin's: the tenant's).
  • Errors: UNAUTHENTICATED with no signed-in caller. FAILED_PRECONDITION on a runner, or on a process that records no run history. NOT_FOUND when the run is not in the caller's history. UNAVAILABLE when one of the run's records cannot be read: the graph is then unknown, never empty.

The graph behind Graph on the Options page: the run's question, its business areas, their scenarios, and what each scenario rests on, read from the run's stored records with no model call. Node kinds: RUN (or ESTATE when no run is named: the caller's newest run), DOMAIN, SCENARIO, PROPERTY (a lever its simulation tested), EDGE_TEST (the link between two areas a synapse scenario crosses), TERM (a metasearch topic or market subject), TABLE, RULE and VERDICT. A node is identified by the record's own key (term:<normalised term>, rule:<rule id>, table:<table>, edge:<a>|<b>), so a leaf several scenarios share is one node with an edge from each; what differs per scenario (a property's result, the terms a scenario triggered across an edge test) is on the edge. A kind the run recorded nothing for is listed in gaps with the reason.

Request: GetScenarioGraphRequest

Field Type Description
transaction_id string The run. Empty: the caller's newest run, under an ESTATE root.

Response: ScenarioGraph

Field Type Description
transaction_id string The run read; empty when the caller has none.
root_id string The root node.
nodes repeated ScenarioGraphNode id, kind, label (the record's own text), scenario_id and domain for a scenario, status, facts (key and value), sources and ran_at for a term, and measured with not_measured_reason.
edges repeated ScenarioGraphEdge from_id, to_id, the link's facts, and triggered_terms on a scenario → edge-test link.
gaps repeated ScenarioGraphGap A node kind the run recorded nothing for, and why.
run_verdict RunVerdict The run's strict verdict, when it recorded one.
computed_unix_ms int64 When the graph was built (kept for 5 s per tenant and run).

verdict RunVerdict The run's strict verdict. Absent for a run that answered before its phases were recorded: such a run is not successful.
verdict_unreadable string Set when the run's phase ledger could not be read, in the server's words. verdict is then absent because nothing was read, which is not the same as a run that recorded no ledger.
archived, archived_by, archived_unix_ms bool, string, int64 Set only with include_archived: the run is archived, by whom (the verified subject) and when.
persona_id, persona_name string Who the run was made for, and that persona's name when the run arrived. Both empty for the generalist view.

RunVerdictOutcome

Value Meaning
RUN_VERDICT_OUTCOME_UNSPECIFIED Not set.
RUN_VERDICT_OUTCOME_SUCCESSFUL It answered, and every phase is done.
RUN_VERDICT_OUTCOME_PARTIAL It answered, and at least one phase is not done. A phase left running more than 46 minutes after the run's last update reads as not_run, with the reason the server stopped before it finished.
RUN_VERDICT_OUTCOME_FAILED It did not answer: it failed, was refused or was interrupted.
RUN_VERDICT_OUTCOME_RUNNING It has not answered yet, or a phase after the answer is running.
