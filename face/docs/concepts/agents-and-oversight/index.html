Agents & oversight

Agents & oversight

FACE's agents draft; a person decides. Nothing an agent proposes is sent, filed or paid until a named person approves it on Actionable Twins, and FACE recommends an option only when it is clearly better on the data.

The agents are driven by one orchestrator, the Ralph loop. What an agent may do is bounded by guardrails on its input, a review of the actions it proposes, and a human decision before anything is adopted.

The Ralph orchestrator

RalphOrchestratorService.ExecuteLoop runs an agent loop (thought, then action, then observation) and streams each step back as an ExecuteLoopResponse:

  • agent_id picks the template, for example twins, hypothesis or rules_recon.

  • LoopStatus reports progress: WORKING, EXECUTING, OBSERVING, DONE, FAILED or MAX_REACHED.

  • On DONE, judgements carries the reviewer's verdicts.

The same loop drives the scenario simulations behind Options and the interactive twin (StreamTwins).

Agent templates

The loop serves these agent templates: twins, hypothesis, rules_recon, ai_posture, compliance, finance, claims, claims_leakage, fraud_detection, fulfilment, reverse_logistics, route_twin, predictive_maintenance, telemetry, documentation, vision, voice, cop and self_healing.

Other analyses, such as the market and due-diligence passes, run outside the loop.

Tools

The loop can dispatch three tools, each authorised against the caller's verified identity:

Tool Tier What it does
read_file read Reads a file from a confined path. Output is truncated.
run_sql write Runs a read-only query against the connection the loop was started with.
delegate_to_claims invoke Hands a sub-task to the claims agent.

Agents that run on their own

No one picks an agent and presses Run. The server runs the agents a change makes stale, for the tenant it happened in:

  • A rule's enforcement posture is saved (RulesService.UpdateRulePolicy, from the policy drawer on Why): compliance and twins run.
  • A scenario is simulated (SimulateScenario or InteractiveSimulate): twins runs, to turn the outcome into proposals.

Changes made close together are combined into one run per agent. These runs are named auto:<agent>, and Options shows the ones in flight in one line (nothing at all when none is running). What they propose still waits for a person on Actionable Twins.

Guardrails (OpenBias)

Before a prompt reaches the model, FACE checks it against guardrail rules. The rules cover each service's entry points, GenerateSOP, GenerateRoadmap, TriageReturnItem and camera-feed grading included. Every refusal is audited.

Review of proposed actions

Every proposed action is independently reviewed before a person decides. The reviewer's verdict is shown on the card. An action the review does not support is not offered for approval, and one that was not reviewed is shown as not reviewed, never as accepted.

Human-in-the-loop points

A person makes these decisions. The server records who made each one, from the verified session:

Decision Where RPC What's recorded
Send an option for approval Options HypothesisService.SendToTwins The option, its figures as the server computed them, and the approval it needs. Sending decides nothing.
Approve or reject an action card Actionable Twins TwinsService.ExecuteAction decision_trail. A reason is required on rejection. Approval seals the evidence document. A two-person card needs two different named people.
Make an approved decision a standing rule Actionable Twins, on an approved card TwinsService.ProposeStandingRule / ApproveStandingRule Proposer and approver; the approver must be an org admin who is not the proposer.
Address a remediation order Actionable Twins and its remediation views ComplianceService.AssignRemediation assigned_by and assigned_at_unix
Standing routing rule The remediation views SetRemediationRoute set_by and set_at_unix
Decide a remediation order Actionable Twins and its remediation views DecideRemediation decided_by and decided_at_unix
Set a rule's enforcement posture Why, the rule's policy drawer RulesService.UpdateRulePolicy The operator-owned half only. It can't change findings.
Read actual customer rows API only; the FACE app does not call it ConfigService.SampleConnectionDataset A separate, bounded call. Exploring a source never samples it. See Data sources.

Nothing FACE derives is sent, filed or settled without one of these decisions. Where an action does execute, for example an email draft through a connected account, its outcome is reported per artifact in not_executed. See Action cards & money.

Reading the results

  • Guardrails make misuse harder; they don't make it impossible. A prompt fence makes injection harder, and it does not solve it.
  • A review is a second opinion. A supporting verdict does not show the action is right.
  • Recording a human decision is not enforcing it. The recorded decision shows who approved what. It doesn't show that they reviewed it carefully.
