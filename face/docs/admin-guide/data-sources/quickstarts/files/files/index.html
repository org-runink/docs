Files

Files

Warning: The test-estate safety rule: stand the test estate up only beside a test instance, never a production deployment. Its systems are throwaway test services with published credentials: change-me is every test credential. They are still encrypted and still ask for a login, because FACE refuses a connection that is not (see Connector security). Use a scratch machine or a scratch cluster.

Grade D · dataset: Files (real PDFs, images, video and sheets)

What it is

The Files dataset: the estate's documents, images, video and sheets, each laid out under the store it would live in (s3/, gcs/, azure/, sftp/, sharepoint/ and host/). It holds claim and invoice PDFs, dock photos and labels, dock video clips, a rate sheet and proof-of-delivery export, a carrier scorecard workbook, and an orders export. The connector reference is Files and object storage.

Grade

D. Dataset and model: the quickstart dataset and its expected model ship. There is no vendor system to stand up for this type; load the dataset and fetch it.

See the grade table for all 32 types.

Stand up the test system

The safety rule at the top of this page comes first: a scratch machine or a scratch cluster, never a production or platform one.

  1. Download files.zip and unzip it. Each store has its own folder under files/: s3/, gcs/, azure/, sftp/, sharepoint/ and host/.
  2. Put each folder where its store expects it: upload files/s3/quillmere-claims/ to a bucket named quillmere-claims in an S3-compatible store you own, served over https:// (MinIO is one open-source option), files/gcs/ to a GCS bucket, and so on.

  3. Connect each store, in Settings › Integrations › Systems, with the connection type that reads it:

    • many documents under one bucket and prefix, on an S3-compatible store, GCS or a SharePoint library: a files connection, with provider naming the store;
    • delimited files, JSON and Parquet in a bucket, one object as a table: objectstore;
    • a workbook read from a path: excel;
    • a SharePoint list: sharepoint.

    A files connection does not read the azure/, sftp/ or host/ folders: providers azure, sftp and host are refused when the connection is tested, before anything is dialled. Those folders are here as the shape of the estate's files.
