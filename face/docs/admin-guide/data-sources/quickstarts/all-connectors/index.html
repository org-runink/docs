See all connectors at once

Warning: The test-estate safety rule: stand the test estate up only beside a test instance, never a production deployment. Its systems are throwaway test services with published credentials: change-me is every test credential. They are still encrypted and still ask for a login, because FACE refuses a connection that is not (see Connector security). Use a scratch machine or a scratch cluster.

This is the end-to-end walkthrough: one company in every connector, and FACE making sense of all of them together. Every source below is a view of the same company, Quillmere Freight Lines (quillmere.invalid). A shipment in PostgreSQL is the same shipment in the Kafka events, the GPS track, the SAP delivery, the Salesforce case, the claim PDF, the dock-camera frame and the RFID read. Six anomalies are planted across the sources, and each one can only be seen by reading more than one of them.

The universe

As of 2026-09-30, at seed 20261005. People appear only as roles. Every host ends in .invalid, every address is in a documentation range, and the only credential value is change-me.

The walkthrough

Connect the sources in this order. Each step adds a kind of source, and each step has something to show.

  1. Connect the two databases FACE reads end to end

    Load postgres and mysql into scratch engines and add both connections. Explore returns their tables, columns, types, primary keys and declared foreign keys: the operational system (customers, orders, shipments) and freight billing (carriers, rate contracts, invoices). These two are the ones a test checks against the expected model, so start here.

  2. Add the event bus and the telemetry

    Stand up kafka, or the live Kafka estate for a stream that does not end, and use the recordings for mqtt, iot, gps, rfid, sensorgateway and cctv. Kafka shows its topic list and value schemas. Its Schema Registry and ksqlDB add which business domain each topic's schema belongs to, which topic a query computes from which, and which topics carry no traffic. The telemetry sources have no catalogue: FACE collects for a window and infers each feed's shape, and the reader location, the GPS asset_ids and the gateway channels settings tie readings to docks and trailers.

  3. Add the business apps and the systems of record

    Add salesforce, sap, guidewire, servicenow, hubspot, d365, sharepoint and github, then the logistics systems: oms, tms, whs, yms, ims, inventory and logisticsapi. Each page says what FACE reads for that type. Where FACE reads no catalogue, open the payload next to its expected model: the shared keys are the same strings.

  4. Add the files

    The files dataset lays the estate's files out by the store each would live in: claim and invoice PDFs on S3, dock photos on GCS, dock video on Azure, the carrier rate sheet over SFTP, the scorecard on SharePoint, and an orders export on the runner's disk. The PDFs are real PDF text, the images decode and the clips are MJPEG. Its page names the connection type that reads each store. excel, document and objectstore hold three more small datasets.

  5. Add the cloud warehouses

    snowflake, databricks, redshift and bigquery need a cloud account. Load their SQL into an account you own. Against a real account, FACE reads the Snowflake and Databricks catalogues; for Redshift and BigQuery, show the dataset next to its expected model.

  6. Walk the six anomalies

    Take them in the order below. Each one names the sources that hold its evidence, the file, and the literal string to look for, so every claim made on screen can be checked against the data.

What the test estate shows, and what it does not

  • It shows every connection type's native shape, the shared keys that join them, and evidence that only adds up across sources.
  • A test measures FACE's discovery against the expected model for PostgreSQL and MySQL. For every other type, the expected model is the shape the source holds, and each quickstart says what FACE reads for that type.
  • It is not product data. The FACE backend reads none of the test-estate data at runtime.
